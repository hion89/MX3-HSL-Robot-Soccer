# RViz 관측 표시 / HSL observer — 2026-11-12

현재 로봇의 이름·역할·경기 상태·스킬, 실제 이동 목표, 추정 공 위치, 원시 3D 관측 마커를 표시한다. 기존 20261109 뷰어는 보존한다.

- 파란 화살표: 추정 로봇 위치·방향. 라벨은 hostname 앞부분(robo04-desktop → robo04)을 기본으로 사용한다.
- 분홍 화살표와 연결선: 행동 코드에서 이번 주기에 호출한 WalkToPose의 실제 목표. 방향은 목표 heading이다. 회피 속도까지 포함한 계획 경로를 뜻하지 않는다.
- 주황 공: /hsl/ball의 추정 위치. 좌표와 마지막 관측 경과시간 표시.
- 작은 색상 사각형과 클래스/신뢰도: /perception/detections_3d의 원시 검출. L은 청록, T는 초록, X는 자홍, 골대는 노랑이다. 모든 원시 검출이 자기위치 추정에 채택됐다는 뜻은 아니다.
- 관측은 해당 검출 stamp의 TF를 사용해 map에 변환한다. identity/latest 변환으로 대체하지 않는다. 변환이 없으면 화면 상태에 표시하고 점을 생략한다.
- 제자리 회전, 대기, 킥 중 등 WalkToPose 호출이 없는 구간은 이동 목표를 표시하지 않는다. 텔레옵의 속도 명령에는 목적지가 없으므로 가짜 목표를 만들지 않는다.
- 행동 정보가 1초 이상 갱신되지 않으면 unknown으로 표시하고 목표를 숨긴다. 관측은 약 0.8초 내의 것만 표시한다.

## 적용 범위

observer는 MarkerArray만 발행한다. cmd_vel, joint_goals, initialpose, TF를 발행하거나 토크 서비스를 호출하지 않는다. 행동 패키지의 두 파일에는 목표 표시용 필드만 추가한다. 기존 속도 계산, 역할 배정, 도착 래치, 보행/킥 파라미터는 유지한다.

정지한 상태에서 apply_behavior.py를 실행하고 hsl_behavior만 재빌드한다. 빌드는 --base-paths src를 사용한다. 로봇에서 새 행동 코드가 동작하려면 start.sh를 재시작해야 한다. 이 과정에서 역할 시험이 중단되므로 재시작 후 role.sh로 역할을 다시 시작한다. 기존 초기 위치 입력값은 로봇이 실제 그 위치에 있을 때만 재입력한다.

MobaXterm X11 forwarding이 설정된 SSH 터미널에서:

```bash
bash /home/robo04/incoming/hsl_view_20261112/start.sh
```

이름을 명시하려면:

```bash
ROBOT_NAME=robo04 bash /home/robo04/incoming/hsl_view_20261112/start.sh
```

새 start.sh는 실제 자기위치 노드의 practice/s_field 설정을 읽는다. FIELD_PROFILE을 바꾸거나 로봇의 지도 설정을 수정하지 않는다.

현재는 한 로봇의 로컬 ROS 도메인을 보는 구성이다. 이름을 robo03으로 지정하는 것만으로 다른 로봇의 데이터를 가져오지는 않는다. 여러 로봇을 한 RViz에 모으려면 별도의 통신/좌표 변환 구성이 필요하다.

## 검증 한계

로컬에는 ROS Humble과 RViz 실행 환경이 없다. 순수 좌표 변환/표시 데이터 검사, 원본 대비 스킬 출력 회귀 검사, ROS 메시지 모형을 사용한 렌더링 검사와 설치 파일 검증을 수행한다. 실제 TF 수신과 X11/RViz 표시는 로봇에서 확인해야 한다.
