# robo04 한 대의 실제 역할 실행

목표는 제공된 보행·킥 정책과 기존 B-Human 이식 전략을 실제 로봇에 연결하는 것이다.
가중치, 관절 순서, action scale, 게인, IMU 보정은 바꾸지 않는다.
보행은 hsl 최종 v0_6 13500, 킥은 hsl 최종 v1_5b 22300을 명시적으로 사용한다.

원본 자동 전략에서는 필드 로봇 한 대가 계속 공 담당으로 선택된다.
assigned_role=attacker/defender/goalkeeper를 추가해 같은 robo04에서 역할을 바꿀 수 있게 했다.
역할 동작은 원본 공 접근·킥 스킬, defender_pose, goalkeeper_pose를 재사용한다.
수비 거리의 9m 경기장 기준 상수는 practice 지도 길이 비율에 맞춰 줄인다.
작은 연습장에서 수비 목표가 공보다 상대 골대 쪽에 생기던 배치를 바로잡는다.
골키퍼는 우리 페널티 구역의 공만 직접 처리하고, 그 밖에서는 골문 앞 위치를 조정한다.
auto는 기존 팀 역할 배정을 유지한다. 기존 ROLE_NONE가 공 담당 표시에도 남던 fallback도 수정했다.

## 배포

기존 터미널 7의 shadow 행동만 Ctrl+C로 종료한다. 1~6 하드웨어/센서/월드모델은 유지한다.
apply_and_build.sh는 원본 해시 확인/백업/6개 파일 적용 후 4개 관련 패키지만 빌드한다.
새 실물 기동 파일은 기존 하드웨어/카메라/월드모델을 중복 시작하지 않는다.

start.sh는 실제 명령 경로(중재기→보정→보행·킥)와 원본 낙상 처리기, 역할 행동을 실행한다.
처음에는 INITIAL/gait stop으로 대기한다. 걷는 위상은 정지지만 정책의 정지 관절 목표는 실제로 적용된다.
role.sh attacker/defender/goalkeeper 명령으로 PLAYING에 진입한다.
role.sh stop은 행동 정지, 보행 위상 정지, 진행 중 킥 종료를 요청하고 토크는 유지한다.
role.sh attacker --seconds 10처럼 실행하면 지정 시간 뒤 자동 정지한다.
시간 옵션을 생략하면 role.sh stop을 실행할 때까지 역할을 계속 수행한다.

실물 첫 역할 실행에서는 로봇이 START로 기립된 상태여야 한다.
행동 속도 상한은 최초 시험용으로 전진0.20m/s, 횡0.15m/s, 회전0.50rad/s다.
기존 배치와 practice 초기 위치를 그대로 사용한다. START는 위치 초기화보다 먼저 누른다.

## 통합 수정 범위

- 기존 control.launch에 킥 모델 경로, 실행 provider, 정지 유예 인자를 전달한다.
- CPU provider를 명시해 실행 시 TensorRT 컴파일 대기를 피한다.
- 로컬 역할 시험의 경기 상태를 외부 GC/자기위치에 발행하지 않는다.
  행동 노드가 자기 상태에 따른 game_stop_lock을 발행하고, 기존 teleop 0 정지 경로를 사용한다.
- 실제 확인된 명령 캐시 문제에는 마지막 cmd_vel 수신 후0.5초에 속도와 위상 주파수를0으로
  전환하는 보호를 넣었다. 새로운 명령을 받으면 재개하며 정책은 정지 추론을 계속한다.
- 킥 motion_enabled는 정지/역할 변경 시 진행 중 킥을 끝내고 소유권을 보행으로 돌려준다.
- 시작은 gait stop, 정지 유예0으로 두어 속도0의 초기 1초 자동 제자리 위상을 피한다.

로컬 역할/시작·정지/적용 회귀 검사와 Python3.10/Bash 문법을 확인했다.
실제 역할 수행은 배포 후 확인할 대상이며 이 묶음의 생성만으로 실물 성공을 주장하지 않는다.
