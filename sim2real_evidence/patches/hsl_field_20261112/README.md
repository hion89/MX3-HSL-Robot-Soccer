# 사진 기준 연습장 지도 수정 — 2026-11-12

사진에 명시된 값: 라인 3.9×2.6m, 잔디 5×3m, 센터서클 반지름 0.35m, 페널티 구역 깊이/폭 0.87/2.17m, 골 구역 깊이/폭 0.43/1.30m, 골대 기둥 간격 1.13m, 골라인에서 페널티 마크까지 0.65m.

기존 humanoid_localization의 practice는 사진과 같았으나 현재 실물의 HSL C++/Python 지도는 S-Field를 균일 축소해 폭 1.7333/골대 0.78/반지름 0.325를 사용했다. C++ 위치 추정의 선/랜드마크, Python 전략의 필드/골대/골키퍼 구역, RViz를 사진과 같은 명시 치수로 수정한다.

잔디 경계도 5×3m로 수정한다. 골라인 뒤 여유 0.55m, 사이드라인 여유 0.20m다. 기존 C++ 후보 유효 영역은 4.9×3.6m였다. 기본 START 진입 시드가 사이드라인 밖 0.4m로 잔디를 벗어나므로 practice 기본값은 0.10m로 수정한다. s_field 기본값은 0.4m 그대로다. 명시적인 사용자 outside-margin 인자는 계속 우선한다.

기존 약속 시작 좌표(-1.95,+0.7583333,0)는 바꾸지 않는다. 사진에서 왼쪽 두 T 마커는 y=+0.65,+1.085이며 정확한 중간은 +0.8675이다. 실제로 그 중간에 놓는다면 기존 seed와 약 10.9cm 차이가 있으므로 실측 후 seed를 맞춰야 한다. 이 수정은 로봇을 다른 위치로 이동시키지 않는다.

## 영향

- 기존보다 랜드마크 후보와 선 위치가 달라져 위치 추정 값, map→odom TF, 공의 지도 좌표가 변할 수 있다.
- 골대 폭 수정으로 골키퍼 일반 좌우 제한은 ±0.24에서 ±0.415m로 바뀌며 공 직접 처리 영역도 사진의 페널티 구역 기준으로 넓어진다.
- 보행/킥 모델, 관절 매핑, PID, 속도/hold/필터 튜닝은 수정하지 않는다. 경기 상태/역할 결정 알고리즘은 유지하되 입력 지도 치수는 수정된다.
- s_field 9×6m의 기존 치수는 유지한다. MuJoCo의 제공된 scene_*.xml은 s_field용 물리 장면이며 이번 수정에서 변경하지 않는다. practice 소프트웨어 지도만 켜도 그 물리 장면이 연습장으로 바뀌지는 않는다.

## 적용

로봇을 지지하고 기존 teleop/역할 제어/start.sh/base.sh/구 RViz를 종료한다. apply_and_build.sh는 실행 중인 관련 노드가 있으면 중단한다. 소스 해시 검사 후 백업하고 hsl_world_model과 hsl_behavior를 빌드한다. Python 지도 대조와 C++ 헤더 실제 컴파일/랜드마크 검증을 함께 수행한다.

빌드 후 base.sh → start.sh 순서로 다시 켜고 새 RViz는 이 묶음의 start.sh로 연다. 자기위치 노드를 재시작하므로 기존 추정 상태가 초기화된다. 약속한 실제 위치에 다시 배치한 경우에만 물리 START 뒤 기존 init_pose.sh로 seed를 넣는다. 움직인 위치에서 예전 seed를 그대로 입력하지 않는다.

이번 뷰어는 20261112 표시 확장을 포함한다. 이름/역할/원시 관측/실제 이동 목표/공을 표시하고 잔디 외곽과 도면 치수를 추가한다. 원시 관측이 전부 위치 추정에 채택됐다는 뜻은 아니다.

## 되돌리기

출력된 runtime_logs/practice_photo_* 백업에는 바뀐 파일의 원본이 있다. 지도와 뷰어를 함께 되돌리고 hsl_world_model/hsl_behavior를 재빌드한 뒤 노드를 재시작해야 한다. 일부 지도 파일만 되돌리면 다시 서로 다른 규격을 쓰게 된다.
