# 킥 후 디딤발 붕괴 — 원인 후보별 MuJoCo sim2sim 측정 (2026-11-16)

이 문서는 시뮬레이션 측정 결과다. 실제 로봇은 이번 작업에서 구동하지 않았고, 서버 학습도 아직 실행하지 않았다. 숫자는 원인 후보의 상대적인 크기를 비교하는 근거이며, 실물의 원인을 확정하지 않는다.

## 무엇을 측정했나

- 대상 정책: 현재 실물이 쓰는 `walkkick_v1_5b_22300.onnx`(= `XM_Kick_Policy/policy/policy.onnx`, SHA256 f71c4db1…3779f).
- 물리: 저장소의 `MX3_Match_Sim/src/humanoid_sim/models/scene_1v0.xml`(MuJoCo 브리지와 같은 로봇·공·바닥), MuJoCo 3.3.0, 물리 5ms, 정책 50Hz.
- 평가기: `mujoco_kick_stress.py`. ROS 없이 실물 러너(`actor_onnx_walkkick_v1_runner.py`)의 관측 구성을 재현한다. 재현 항목은 프레임 53×5와 term-major 순서, 보행 위상, hold 중 명령 0과 hold 중 추론, 행동 필터, 브리지와 같은 1주기 goal 지연, Profile Velocity 45rpm이다. 모터 명령은 보내지 않는다.
- 시작: 서서 시작(1초 안정화 후 트리거). 공 0.2~0.5m, 방위 ±70°, 목표 ±90°, 세기 1. 조건마다 seed를 고정해 300회 반복했다.
- 넘어짐 판정은 학습 종료 조건과 같다(기울기 0.6rad 또는 몸통 높이 0.28m). 트리거 후 3초 동안 킥 정책이 계속 제어한다.
- 평가기 검증:
  - 학습과 같은 관측 순서에서 전도율 2.3%, 공속 4.55m/s가 나왔다. 원 작성자의 MuJoCo 기록(서서 0~1%, 공속 4.5m/s)과 같은 수준이다.
  - IMU 20ms 지연에서 크게 나빠지는 경향도 원 기록(MATCH_FALLS_22300.md)과 일치한다.
  - 저장소 체크포인트 model_22300.pt를 torch로 내보낸 ONNX는 원본 ONNX와 출력 최대 차이 0.0이고 gate 점수도 같다.

## 결과 (22300, 세기 1, 300회, ±는 95% 구간 근사)

원본: `results_22300_full/summary.json`, `results_22300_gate*/summary.json`. 각 줄은 "조건 → 전도율"이다.

러너와 배포 계약:
- 학습과 같은 관측 순서 → 2.3%(±1.7).
- 실물 러너 관측 순서(센서가 한 틱=20ms 늦음) → 13.0%(±3.8). 이후 조건은 별도 표시가 없으면 이 실물 순서를 기준으로 한다.
- 실물 계약(hold 0.6, 접근 0.20, 필터 τ 0.02) → 10.0%. 필터만 → 14.7%, hold 0.6만 → 12.3%, 접근 0.2만 → 7.7%.
  사용자가 접근 속도를 낮춘 뒤 "조금 나아졌다"고 관찰한 것과 같은 방향이다.

구동기(XM540-W150 속도-토크 곡선, Isaac Lab DCMotor와 같은 사분면 규칙):
- 12V → 26.7%, 11.1V → 33.7%, 10.6V → 33.3%. 공속은 4.70에서 4.08~4.37m/s로 줄었다.
- 학습은 관절 속도와 무관하게 5N·m를 준다. 그런데 킥 스윙 속도(4~4.7rad/s)에서 실제 모터가 낼 수 있는 토크는 1.1~2N·m다.
- 실물 bag에서도 0.31초에 발목 roll 목표 -31.9°에 비해 실측이 -0.7°였고, 전압은 10.6V까지 떨어졌다.

지연:
- IMU 지연 10 / 20 / 40ms → 21.7 / 44.0 / 81.7%.
- 행동 지연 +1 / +2 / +3스텝 → 23.7 / 28.0 / 35.3%.

바닥:
- 미끄럼 마찰 0.6 / 0.5 / 0.4 → 23.3 / 38.7 / 66.7%.
- 접촉을 부드럽게 한 잔디(시간상수 0.05초) → 3.7%. 단독으로는 영향이 작았다.
- 비틀림 마찰 0.5 / 0.2(기본) / 0.1 / 0.05 / 0.02 / 0 → 7.0 / 13.0 / 9.3 / 0.3 / 0 / 0%.
  같은 조건에서 킥 후 1초 안에 디딤발이 돈 각도(p90)는 5.5 / 8.7 / 13.5 / 21.7 / 35.1 / 45.6°다.

실물에 가까운 복합 조건(`real_like`: 11.1V 곡선 + IMU 10ms + hold 0.6 + 접근 0.2 + 필터 + 미끄럼 0.6 + 비틀림 0.1):
- 세기 1 → 78.3%, 미끄럼 0.45로 낮추면 → 89.0%.
- 세기 0.75 → 29.0%(저마찰 57.0%).
- 세기 0.5 → 0.0%(저마찰 9.3%). 공속은 3.25m/s.

킥 세기 0.5에서는 위의 단일 조건(DC 11.1V, IMU 20ms, 행동 +2, 미끄럼 0.5 포함)이 모두 0~0.3%였다.

## 해석

1. 한 가지 원인으로 설명되지 않는다. 학습 조건에서 3% 이하인 정책이 구동기 곡선, 관측 지연, 미끄럼 마찰 각각으로 20~45%까지 나빠지고, 겹치면 80% 안팎이 된다. 바닥 재질은 여러 원인 중 하나다.
2. 22300은 세기 1에서 안정 여유가 거의 없다. 같은 정책이라도 세기 0.5에서는 대부분의 악조건에서 거의 넘어지지 않는다. "최대 킥 동작" 자체가 여유 없는 해에 수렴해 있다는 뜻이다.
3. 디딤발 회전은 원인이자 결과다. MuJoCo에서는 비틀림 저항을 0에 가깝게 줄이면 발이 30~45° 돌면서 반동이 빠져나가 오히려 넘어지지 않는다. 이는 원 작성자의 헛발질 기록(비틀림 0.2→0.1에서 73→49%)과도 맞다.
   실제 잔디에서는 돌다가 다시 걸리는 stick-slip, 공 방향 오차, 이후 착지 문제가 함께 생길 수 있다. 이 부분은 두 시뮬레이터 모두 재현하지 못한다. 그래서 비틀림만 줄이는 학습은 근거가 약하고, 넓게 섞는 랜덤화가 맞다.
4. 실물 러너 관측 순서가 20ms 지연을 더한다. 러너는 틱 끝에 프레임을 push하므로 다음 추론이 한 틱 전 센서를 본다. 학습 순서와 비교하면 2.3%에서 13%가 된다. 정책을 바꾸지 않고도 줄일 수 있는 항목이다(러너 수정은 실물 코드 변경이라 아직 하지 않았다).

## 한계

- 서서 시작만 측정했다. 걷다가 넘겨받는 상태 은행 시작과 회전 중 넘겨받기는 포함하지 않았다.
- DC 곡선은 ROBOTIS 공칭 스펙(12V 기준 스톨 7.3N·m, 무부하 5.55rad/s)의 선형 모델이다. Dynamixel 내부 전류·PWM 제한, 발열, 기어 효율은 모델에 없다.
- MuJoCo의 비틀림 마찰과 실제 인조잔디의 비틀림 거동은 같지 않다. 공 물성은 기존 브리지 값으로 고정했다.
- 넘어짐 판정 창 3초 동안 킥 정책이 계속 제어한다. 실물처럼 2초에 보행 정책으로 넘기는 과정은 포함하지 않았다.
