## 기존 학습에 이미 있는 조건

- 킥 정지마찰 0.45~1.35, 운동마찰 0.40~1.10, 반발 0~0.2. training/env.yaml에 reset 이벤트로 저장돼 있다. 물성 배정 대상은 robot의 모든 body이다. 지면 물성은 마찰 1.0, multiply 조합이다.
- 액션 지연 1~4 제어 스텝, 목표 추종 Profile Velocity 40~50rpm.
- 85%는 보행 13500 넘겨받기 상태 은행에서 시작하고 15%는 기립 상태. 은행 파일 약 24.96MB가 포함돼 있다.
- 기본자세 hold 0.3초, 시작 위상 0, 킥 세기 0~1을 학습한다. 공 위치 frozen 관측을 유지한다.
- support_slip(-0.5), capture_point(+1.0), base_yaw_rate_limit(-0.5), fall_after_kick(-300.0) 보상이 저장돼 있다. 가중치 수치만으로 영향력을 비교할 수 없다.
- support_slip은 접촉 센서로 접촉 판정된 발 링크의 수평속도 제곱을 합산한다. 실제 접촉점 미끄럼 또는 지지발만을 분리한 측정과 동일하지 않다. 공 접촉/차는 발과 바닥 지지 접촉을 구분하는지 검증이 필요하다.
- IMU 지연 민감성과 특정 방향 킥 실패는 MATCH_FALLS_22300.md의 기존 실험 보고이다. 원시 실험을 여기서 재현하지 않았고, 현재 실물 원인이 동일하다는 증거는 아니다.
- TERRAIN_ROUGH=False. 주석상 기존 공 스폰이 평지 높이를 가정한다. 요철 도입 전 공/로봇 리셋을 지형 높이 인식형으로 수정하고 관측 frozen 조건과 충돌하지 않는지 검증해야 한다.
- 원래 hold 0.3초와 현재 사용자 시험의 0.6초는 다르다. 현재 시험은 접근 0.20, 필터 tau 0.02, 총 킥 시간 2초를 목표로 수정했다. 서버에서 학습한 조건과 로봇 배포 조건은 반드시 한 계약으로 기록한다.

## 목표와 변경 범위

우선 기존 22300에서 이어 학습하는 잔디 대응 킥 후보를 만든다. 보행과 기상은 기준 모델로 고정한다. 재학습 성공 기준은 발차기를 회피해서 얻는 낮은 전도율이 아니라 유효 킥을 유지하면서 지지발 미끄러짐과 전도를 줄이는 것이다.

관측 265, 출력 12, 관절 순서, action_scale 0.25를 유지한다. 새로운 표면 조건을 정책에 직접 추가 관측하지 않는 한 현재 러너와 모델 입출력을 유지할 수 있다. 상위 역할/좌표계/보행 제어를 동시에 수정하지 않는다.

## 실행 단계

1. 서버 재현 환경 고정
   - Git 커밋, Isaac Sim/Lab, PyTorch, rsl_rl, GPU, 실제 모듈 import 경로 기록.
   - 별도 작업공간/브랜치에 킥 overlay와 기준 모델 설치. 기본 저장소 설치 파일은 유지하고 사용자 기존 변경은 덮지 않는다.
   - README의 버전 조합은 기록으로 취급하며 실제 설치 환경에서 검증한다. Isaac 5.x 관절 마찰 호환 코드를 함께 확인한다.

2. 22300 기준선 재생
   - 원본 학습 계약(hold 0.3, 접근 기본 0.3, 필터 없음)과 현재 실물 시험 계약(hold 0.6, 접근 0.2, tau 0.02)을 분리 평가.
   - 센터 공/좌우 공, 기립/보행 후/회전 후 시작, 저/중/고 마찰, 센서 지연 조건을 고정 seed로 평가.
   - 모델을 학습하기 전에 실제 지지발 미끄러짐이 평가 지표에 잡히는지 확인한다.

3. 표면 물성 랜덤화 개선
   - 초기에는 평지를 유지한다. 바닥의 색/텍스처는 주된 대상이 아니다.
   - 발바닥 접촉에 작용하는 정지/운동 마찰과 낮은 반발을 모델링한다. 운동마찰≤정지마찰을 보장한다.
   - 기존 전신/shape별 독립 배정과 비교해 환경별 공통 표면을 우선 배정하고, 좌우 발 차이는 제한된 범위에서 추가한다.
   - 실측 전 저마찰 탐색 범위 예시: 정지 0.30~1.35, 운동 0.25~min(1.10, 정지). 이는 미확정 실험 범위이며 실물 마찰 추정치가 아니다.
   - 기존 분포도 유지하고 낮은 마찰 비중을 커리큘럼으로 늘린다. 환경별/발별 실제 적용 물성과 조합 후 접촉값을 기록한다.
   - startup/reset 배정의 학습 다양성과 CPU 비용을 비교한다. 매 물리 스텝 물성을 무작위로 바꾸지 않는다.

4. 지연과 구동 응답 보완
   - 자이로와 중력 관측 지연 0~40ms를 탐색 후보로 둔다. 기존 지연 민감성 보고가 근거이며 실물 측정 후 분포를 조정한다.
   - 기존 행동 지연 1~4스텝은 유지하면서 독립 효과를 비교한다. 필터를 배포할 경우 필터 상태 초기화와 last_action 관측 순서까지 러너와 맞춘다.
   - 모터 속도-토크 특성은 별도 실험으로 검증한다. DC 모델을 기존 모든 태스크에 전역 적용하거나 모터 스펙을 확정 실측값처럼 사용하지 않는다.

5. 필요 시 보상 개선
   - 기존 support_slip 벌점의 지지발 선택, 바닥 접촉, 발 링크 원점 속도/실제 접촉점 속도의 차이를 검증.
   - 차는 발을 억제해 무동작 정책을 만드는 것을 방지한다. 유효 킥 성공/공 이동/방향 오차와 함께 점수화한다.
   - 지지발 수평 미끄러짐, 발 회전, 균형 회복을 보강하되 단순 발 벌림 상수나 큰 자세 벌점으로 굳히지 않는다.

6. 이어 학습과 후보 선택
   - model_22300.pt에서 시작. 체크포인트 전체 재개와 actor-only 재개의 차이를 검토한 후 사용한다.
   - 첫 단계는 actor/critic 구조와 PPO 대칭 설정을 유지. 새 실험에서 1e-4 수준의 작은 학습률은 후보이며 고정 정답이 아니다.
   - A: 표면만, B: 표면+관측지연, C: B+지지 보상 개선을 분리해 기여를 확인한다. 필요 시 구동기 모델을 다음 별도 실험으로 추가한다.
   - 마지막 체크포인트를 자동 채택하지 않는다. 미학습 seed/표면 조합과 좌우 킥별 평가 후 MuJoCo에서도 비교한다.

7. 실물 연결
   - 배포할 필터/hold/속도/주기/관절맵을 모델 메타데이터로 고정한다. 현재 2초에는 hold가 포함되며 0.6초 hold면 정책 구간은 약 1.4초이다. 새 후보의 발 회수 완료 시각에 맞춰 총시간을 별도 선정하고 watchdog/상위 timeout도 함께 맞춘다.
   - 기존 모델을 보존하고 후보 경로로 선택한다. 텔레옵 비교 후 자율 역할, 이후 팀 경기 순서.
   - 공 접촉/회복을 확인한 유효 킥 비율, 전도, 미끄러짐, 공 이동 거리/방향, 관절 추종, 전압/전류를 함께 기록.

## 제안한 통과 기준 — 아직 달성하거나 확정한 수치가 아님

- 대표 저마찰 조건에서 기존 22300 대비 전도율을 최소 절반으로 줄이는 것을 1차 목표로 한다. 기준 전도가 충분한 조건에서 비교한다.
- 정상 표면의 유효 킥 성공률은 기준보다 5%p 이상 떨어지지 않고, 공 이동 성능도 유지할 것.
- 각 평가 cell은 고정 seed로 최소 수백 회를 목표로 하되 필요한 표본과 신뢰구간은 기준 실패율/계산 자원에 맞춰 정한다. 조건별 결과를 평균 하나로 합쳐 취약 조건을 숨기지 않는다.
- 시뮬 기준 통과와 실물 검증은 구분한다. 시뮬 평균 성능만으로 실물/4v4 성공을 선언하지 않는다.
