# v1_5b model_22300 — ROS 경기 시뮬에서 남은 킥 넘어짐 (2026-11-02, hsl 세션 분석)

다음 킥 학습·체크포인트 선택용 인계 자료. 경기 숫자는 ROS 4v4 경기 시뮬 (hsl_src + mx3_src 러너 + MuJoCo 브리지,
세기 1 고정) 22300 킥 527 회 (14 판: kick_duration 2.0 s 11 판, 3.0 s 3 판) 에서 나왔다.

## 요약

1. 22300 은 경기에서도 기존 W90B70 18200 보다 낫다 (킥 중 넘어짐 8.5 → 5.3 %, 공 이동 1.85 → 2.20 m). hsl 시뮬 기본 킥으로 바꿨다.
2. 남은 넘어짐은 **오른쪽으로 돌며 걷다가 넘겨받아 오른쪽으로 차는 왼발 킥** 에 몰린다. 거울 조건 (왼쪽으로 돌며 왼쪽으로) 은 0 %.
3. **22300 은 IMU 관측 지연에 매우 약하다**: 경기 넘겨받기 재생에서 IMU (자이로·중력) 만 늦추면 0 / 5 / 10 / 20 ms →
   0.2 / 1.3 / 3.2 / 19.7 %. 학습에는 IMU 지연이 없다 (행동 지연 1~4 스텝만). 실기 IMU 는 필터·통신 때문에 10 ms 이상 늦을 수 있어
   **실기 위험 1 순위**로 본다. 22800 은 같은 조건에서 2.1 / – / 2.4 / 3.8 % 로 거의 안 변한다.
4. kick_match_cond.py 기본 재생 (지연 없음) 으로는 경기 넘어짐이 안 보인다 (0.2 %). 피드백 지연을 넣어야 같은 모양이 나온다.

## 1. 경기에서 넘어지는 조건 (22300, 527 킥, 킥 러너 구간 안 넘어짐 27 = 5.1 %)

공이 서 있고 상대가 0.5 m 밖인 360 킥 (넘어짐 8):

| 넘겨받는 순간 | 넘어짐 |
|---|---|
| 몸통 회전 wz < −0.3 rad/s (오른쪽으로 돎) **그리고** 목표 < −10° (오른쪽으로 참) | **6 / 85 (7 %)** — 그중 공 y ≥ +0.15 면 3 / 10 |
| 거울: wz > +0.3 그리고 목표 > +10° | **0 / 87** |
| 그 밖 | 2 / 275 (< 1 %) |

나머지 넘어짐: 상대 0.3 m 안 (다툼) 30 %, 공이 굴러가는 중 (> 0.1 m/s) 15 %.

- 위험 조건의 전형: 공 (0.40~0.45, −0.08~+0.18), 목표 −13~−33°, 몸통 v ≈ (+0.25, +0.17) m/s, wz −0.4~−1.0 rad/s
  (hsl 행동 노드가 공 뒤로 정렬하며 목표 쪽으로 몸을 돌리는 중에 넘겨줌).
- 발: 타격 시각 오른발 1.02 s · 왼발 1.21 s (관절 기록으로 확인). 위험 조건의 넘어짐은 대부분 왼발.
- 넘어지는 모양: 찬 뒤 몸통이 계속 왼쪽으로 돈다 (트리거 뒤 2.0 s 에 +55~63°, 버틴 판은 +10~20° 에서 멈춤),
  45° 도달 1.9~2.2 s (타격 뒤 0.7~1.0 s), 몸 기준 **오른쪽 (디딤발 쪽)** 으로 넘어진다.
- 원인이 아닌 것: 보행 넘겨받기 시각 (kick_duration 3.0 s 로 해도 1.4~2.0 s 넘어짐 그대로), 공 믿음 오차 (추정 vs 정답 ±2~3 cm).

## 2. MuJoCo 재생으로 재현 (`match_handoffs_ros_22300.csv`, 317 건 × 걸음 위상 4)

| 설정 (22300) | 전체 | 우회전+오른쪽 | 거울 | 그 밖 | 경기에서 넘어진 20 건 ×4 |
|---|---|---|---|---|---|
| 기본 (kick_match_cond.py) | 0.2 % | 0.4 % | 0 % | 0.3 % | 0 / 80 |
| 행동 지연 2 스텝 (40 ms) | 2.5 % | 8.1 % | 0.3 % | 1.3 % | 8 / 80 |
| IMU 지연 10 ms | 3.2 % | 6.6 % | 0.3 % | 3.2 % | 7 / 80 |
| IMU 지연 20 ms | 19.7 % | 34 % | 3.8 % | 21 % | 41 / 80 |

피드백 지연 (행동이든 IMU 든) 을 넣으면 경기와 같은 비대칭 (왼발 · 오른쪽으로 넘어짐) 이 나온다.

경기 시뮬의 실제 지연 (브리지 안에서 실측):
- 행동: 정책 goal 은 언제나 다음 주기 (1 스텝, 20 ms) 에 쓰인다 → 재생 기본과 같다.
- IMU: 직접 못 쟀다. 러너가 `/joint_states` 를 `/imu/data` 보다 먼저 구독해 같은 순간 IMU 보다 관절 콜백이 먼저 돌 수 있어
  5 ms 이상 묵은 IMU 를 쓴다. 경기 넘어짐률 (약 5 %) 은 재생 IMU 지연 10 ms 근처와 맞는다.
- 그 밖에 같음을 확인한 것: 물리 (마찰·condim·solref·관절·구동기), 시뮬 시간 (실시간 1.0 배), 넘겨받기 홀드 0.3 s, 기본 관절각, 목 자세.

## 4. 다음 학습에 제안

1. **IMU 관측 지연 도메인 랜덤화**: 자이로·중력 관측을 0~2 정책 스텝 (0~40 ms, 가능하면 물리 스텝 단위) 늦게.
   지금은 바이어스·잡음만 있다 (`base_ang_vel_biased`, Unoise ±0.3).
2. 체크포인트 판정 (sweep_ckpts.sh) 에 경기 넘겨받기 재생 + 지연 조건을 넣는다 (16 코어 각 약 15~30 s):
   ```
   IMU_LAG=0.5 python scripts/kick_v1_5/replay_delay.py scripts/mujoco_sim/match_handoffs_ros_22300.csv out.csv <onnx>
   IMU_LAG=1   python scripts/kick_v1_5/replay_delay.py ...
   DELAY_K=2   python scripts/kick_v1_5/replay_delay.py ...
   ```
3. 위험 조건 (오른쪽으로 0.4~1.0 rad/s 돌며 넘겨받아 오른쪽 15~35° 로 차기, 왼발) 의 비중을 높인다. 거울 쪽은 멀쩡하니
   대칭 증강이 이 비대칭을 못 잡고 있다 (v1_4 때는 반대로 오른발이 약했다).
4. 결과는 ROS 경기 시뮬로도 확인한다: hsl 쪽에서 `STACK_ARGS="kick_actor_path:=<onnx>"` 4v4 (판당 약 7 분, 킥 약 40 회).
