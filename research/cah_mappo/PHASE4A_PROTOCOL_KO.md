# Phase 4A 사전 분석·비교 규약

이번 단계는 연구 문제 검증이며 CAH-MAPPO나 재학습을 포함하지 않는다. 기존 환경·보상·선택 checkpoint를 수정하지 않는다. 신규 코드는 `phase4a/`, 신규 출력은 `phase4a_outputs/study_v1/`에 둔다. 기존 보호 Holdout은 읽지 않는다. Git 커밋·푸시와 외부 접속을 하지 않는다.

## 사전 가설

- H1: 기존 400개 세계에서는 구역 담당자 두 명을 유지하고 worker 둘이 작업을 순차 수행할 수 있다. Fixed의 실제 완료 시각이 마감 이전인지 확인한다. 일시적인 작업 수 초과와 불가능한 작업 스케줄을 혼동하지 않는다.
- H2: 기존 확률적 MAPPO의 큰 공백은 필수 작업 부담보다 불필요한 담당자 이탈·후임 미준비·재할당에서 생길 수 있다. 실제 구역별 공백 구간과 선택·실행·준비 기록으로 검증한다.
- H3: 정상 인계의 기다림과 긴급 작업의 마감 사이에는 이동·속도 차이로 설명되는 상충 관계가 있을 수 있다. 반대로 동일 속도의 빈 worker가 있으면 직접 보내는 편이 충분할 수 있다. 이 음성 대조군을 A로 포함한다.
- H4: 기존 학습된 MAPPO에 실행 규칙을 붙여도 작업 선택 자체가 부적합하면 해결되지 않는다. 이를 인계 학습의 필요성으로 즉시 해석하지 않는다. 새 환경에 대한 분포 이동과 할당 실패를 분리한다.

## 신규 시나리오의 구성 근거

버전 `phase4a-v1`: 2대/1구역/1작업의 설명 가능한 작은 사례와 4대/2구역/3작업 사례를 함께 사용한다. 32초, dt=1초, 용량1, 관측 반경100m/잡음0/지연0을 유지한다. 이동·회전·작업 서비스 모델은 기존 엔진 그대로다.

A는 역할을 유지해도 완료 가능하다. B는 느리고 먼 worker의 직접 완료는 기한을 넘지만, worker가 가까운 구역을 인수하고 빠른 담당자가 작업하면 대기 후에도 완료 가능하다. C는 즉시 전환하면 완료 가능하지만 인계 대기는 기한을 넘는다. 기한은 정책 성능을 본 뒤 맞추지 않고 독립적인 세 가지 결정적 실행 증인의 물리적 완료시간으로 정한다. B/C가 구분되지 않는 물리 조건은 생성 오류로 거부한다.

4대 사례의 다른 worker는 별도의 긴 작업과 후속 작업을 담당한다. 방어·공격 지원 중 장시간 대응하는 상황을 단순화한 것이며, 실제 경기의 발생 확률을 뜻하지 않는다. 동일 세계에서 모든 정책에 동일 위치·속도·서비스 시간·사건을 제공한다. 시간·속도·작업 우선순위의 설계 이유와 비현실적인 가정은 결과에 명시한다.

위험한 C 변형, 인계 도중 위험도 상승, 기존 담당자 고장, 후임 고장을 별도 계열로 둔다. 구역의 `response_limit_s`는 연속 미대응 시간을 허용하는 **평가상 요구사항**이며 상대 공격을 물리적으로 시뮬레이션하지 않는다. CGR 정의를 바꾸거나 이 유예기간을 공백에서 빼지 않는다.

## 비교 규약

기존 중앙 Fixed/Greedy/Exact/Handover와 로컬 Fixed/ETA를 보존한다. 기존 Exact는 매 시점 할당 탐색이며 시간적 최적해가 아니다. 별도의 결정적 no-change/immediate/ready 실행은 가능성의 증인일 뿐 최적성 증명이 아니다.

기존 MAPPO 5개 선택 모델을 결정적 1회·확률적 2회/세계로 평가한다. 원형, 무조건 READY 대기 실행기, 마감·위험 기반 실행기를 비교한다. Actor 입력은 기존 로컬 패킷만이다. 추가 실행기는 **중앙 현재 관측을 사용하는 특권 실행기**로 별도 표시하고 같은 알고리즘/같은 MDP라고 부르지 않는다. Actor의 원래 행동·분포·log-probability는 보존한다. 실행기는 신규 작업을 발명하거나 다른 작업으로 교체하지 않으며, 요청을 보류하거나 후임을 기존 구역으로 준비시킬 수 있다. 준비 때문에 후임의 원래 요청은 지연될 수 있다. 원래 요청이 변경되거나 후임 고장·위험 상승 시 취소를 기록한다.

대기/조기 해제는 실제 후임 도착·가동·용량을 확인한다. 조기 해제는 대기 시 기한 초과, 즉시 출발 시 기한 준수, 작업 우선순위/구역 위험도, 후임 ETA/구역 제한시간의 비율로 판단한다. 규칙의 두 임계값만 Validation에서 선택한다. 후보는 위험 비율 0.5/1/2와 허용 ETA 배수 1/2/4다. 선택 규칙은 작업 성공률 → 구역 제한시간 위반 감소 → 공백 시간 감소 → 변경 횟수 감소의 사전 고정 사전식 순서이며 종합 성능 점수가 아니다. 평가 후 규칙을 다시 조정하지 않는다.

Validation 3개×7계열×2팀 크기=42개, 별도 진단 평가 6개×7계열×2팀 크기=84개를 사용한다. 기존 최종 Holdout 및 기존 400 benchmark와 다른 생성 버전/사건 스트림이다. 진단 결과는 앞으로 최종 미사용 평가라고 표현하지 않는다.

## 지표·검증

기존 지표에 구역별 연속 공백 구간, 공백 에피소드 비율, 상위5% 공백 평균(전체/공백 조건부 별도), 최대 공백, 구역 제한시간 위반, 요청·준비·취소·실패·긴급 해제, 고장 후 물리 커버 복구시간 및 검열을 추가한다. 인계가 없으면 인계 공백은 N/A다. 분모는 실제 구역 개수×32초와 위험 가중 구역시간을 함께 기록한다. 모든 수치는 Ground Truth 원시 로그에서 재계산한다.

유한 고장 복구를 장치 복구 사건과 구역 물리 커버 복구로 구분한다. 고장 후 복구가 없으면 관측된 하한과 검열을 보고하며 0초로 대체하지 않는다. 시드 평균·개별 결과·공통 세계의 대응 차이를 분리한다. 이 소규모 구조 진단으로 실제 경기 일반화나 알고리즘 우위를 확정하지 않는다.
