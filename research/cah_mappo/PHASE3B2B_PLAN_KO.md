# Phase 3B-2B 본학습 설계안 — 미실행

2026-11-18. 이 문서는 Phase 3B-2A 실측을 바탕으로 한 제안이다. 다음 단계 승인, 새 설치, 서버 접속 또는 본학습을 실행한 기록이 아니다. CAH-MAPPO는 아직 구현하지 않았다.

## 본학습 전에 해결할 사항

1. **운용 모드와 모델 선택을 일치시킨다.** 이번 선택은 Validation argmax를 사용했다. A/8 초기 후보는 결정적 성공100%였지만 확률적 성공66.67%였다. 최종 A/8은 반대로 결정적0%, 확률적100%였다. 결정적 배포와 확률적 평가를 함께 보고하되, 주 선택 모드와 보조 모드를 미리 정한다. Test 결과를 보고 모드를 골라 가장 좋은 숫자만 보고하지 않는다.

2. **작업 슬롯 대응을 검증한다.** 기존 정책은 C에서 작업이 보여도 두 번째 구역 슬롯을 선택했다. C를 학습한 정책도 세 번째 작업은 놓쳤다. 동일한 의미의 알려진 작업을 다른 로컬 슬롯에 놓았을 때 행동이 어떻게 변하는지 진단하고, Training의 작업 순서·종류·개수 분포를 점검한다. 공통 작업 인코더나 슬롯 순서 증강이 필요하다면 Standard와 향후 CAH에 같은 인터페이스/인코더를 적용하는 별도 설계 변경으로 기록한다. 이번에는 변경하지 않았다.

3. **D 작업의 발견 가능성을 확인한다.** 센서 범위 밖이고 통지도 없는 작업은 학습 신호만으로 위치를 알 수 없다. 현재 궤적에서 36개 중 25~27개가 미관측이었다. 각 시나리오에서 작업이 기존 알려진 목표 이동으로 발견 가능한지, 공통 순찰 목표가 필요한지, 발생 후 지연된 작업 알림을 허용할지 정한다. 알림은 발생 이전 정보를 주면 안 되며 모든 로컬 정책에 동일하게 제공해야 한다. 발견 가능한 D와 의도적으로 발견 불가능한 스트레스 조건을 별도로 분류한다.

4. **평가 목적과 종료 규칙을 확정한다.** 계속되는 구역 책임의 고정 32초 관측 창을 주 프로토콜로 삼을지 정한다. 현재는 외부 시간 제한이므로 bootstrap=1, trace 연결=0이다. 진짜 유한 임무 종료를 선택한다면 종료 시 가치0을 사용하는 별도 실험이며 이전 결과와 섞지 않는다. 작업 완료 후 복귀까지 포함한 동일 창을 모든 정책에 적용한다.

5. **공통 관측·행동·보상을 고정한다.** 기존 중앙 Handover는 준비 행동과 추가 정보를 가진 참고군이다. Standard에 준비 행동이 없는데 CAH에만 주면 성능 차이가 학습 구조 때문인지 행동 표현 때문인지 분리할 수 없다. 향후 CAH 설계에서 공통 행동 표현, 공통 실행 중재, 추가 알고리즘 부분을 명시해야 한다. 필요하면 공통 행동 공간을 갖춘 Standard를 별도 기준선으로 둔다. 이번 단계에서는 준비 행동을 추가하지 않았다.

6. **정확한 학습 재개를 보완한다.** 현재 checkpoint는 네트워크·optimizer·일부 RNG만 저장한다. 진행 중 환경, 관측 캐시/메시지 큐, 시나리오 커서까지 복원하는 resume 테스트를 본학습 전에 추가한다. 긴 실행 중단 뒤 처음부터 다시 시작한 결과를 연속 학습으로 잘못 표시하지 않는다.

위 조건이 해결되지 않았다고 해서 알고리즘이 나쁘다고 결론내리지는 않는다. 반대로 스텝을 늘리는 것만으로 해결된다고 가정하지 않는다.

## 분리 집합과 Test 사용

이번 Test는 이미 결과를 확인했으므로 이후 설계·디버깅에 사용한다면 개발 자료다. 본학습의 최종 Test는 **새 생성 버전과 사용하지 않은 시드 구간**으로 새로 고정한다. 현재 train/validation/test 구간과 겹치지 않게 하고, 설정·ID·해시 목록을 미리 저장한다.

Training은 현재의 유한 24개 풀보다 넓게 생성한다. Validation은 하이퍼파라미터/보상 후보와 checkpoint 선택 전용으로 유지한다. 별도 Test runner는 선택된 모델 해시를 입력받아 한 번 평가하고, 평가 이후 학습이나 모델 선택을 호출하지 않도록 분리하는 것이 적절하다.

보상 후보는 현재 기본 coverage=2와 강한 coverage=8이라는 제한된 후보였다. 본학습에서 다른 후보를 검토하려면 새 Training/Validation에서만 사전 계획에 따라 조정한다. 성공 보상과 책임 공백을 동시에 유지하고, 보상 변경 효과를 알고리즘 변경 효과로 부르지 않는다. Standard와 향후 CAH는 가능한 한 동일 가중치·평가 기준을 사용한다. 서로 다른 가중치 비교는 보상 민감도 실험으로 분리한다.

## 독립 반복과 평가 표본

출발 기준은 **독립 학습 시드 최소 5개**, 시드별·시나리오 계열별 Test **200에피소드**다. 이는 통계적 충분성을 보장하는 값이 아니다. 현재 학습 반복은 하나뿐이므로 학습 시드 간 분산을 아직 추정할 수 없다.

- 학습 시드가 기본 독립 반복 단위다. 한 시드의 평가200개를 독립 학습200회로 취급하지 않는다.
- 알고리즘 사이에는 같은 시나리오 ID/초기 상태/외생 일정/센서 난수 조건을 제공한다. 정책 샘플링 RNG는 외생 RNG와 분리한다.
- 각 학습 시드의 평균·분산과 개별 결과를 먼저 보고하고, 시드 간 분포와 불확실성을 정리한다. 신뢰구간/재표집은 학습 시드 계층을 보존해야 한다.
- 성공률, 마감 준수율, 공백, 조건부 응답시간, 미응답 비율, 제한 응답시간, 전체 완료시간/미완료, 전환·중복 요청을 따로 보고한다. 임의 가중합 점수로 우열을 정하지 않는다.
- 평가 시나리오를 늘리는 것과 독립 학습 시드를 늘리는 것을 구분한다. 학습 시드 변동이 크면 5개를 넘기는 방안을 예산과 함께 검토한다.

## 단계별 잠정 학습 규모

아래는 실제 실행하지 않은 예산 출발점이다. 먼저 짧은 추가 검증으로 원인이 해결됐는지 확인한 뒤 확정해야 한다.

- A: 학습 시드5개 × 100,000스텝 = 500,000스텝.
- B3: 앞 단계의 사전 성공 기준을 통과하면 5개 × 200,000 = 1,000,000스텝.
- C: 슬롯 문제와 학습 안정성을 확인한 뒤 5개 × 200,000 = 1,000,000스텝.
- 합계 Standard 잠정 2,500,000스텝. 처음부터 모두 실행하지 않는다.
- B2는 별도 학습 또는 전이 평가 중 어떤 목적에 사용할지 사전 정의한다.
- D의 본학습 예산은 발견 가능성과 관측 조건을 정한 뒤 별도로 측정한다. 현재 실패를 단순히 200,000스텝으로 연장하지 않는다.
- 향후 CAH 비교에는 같은 단계·시드·예산을 적용하되, CAH 구현은 별도 승인 이후 작업이다.

Validation은 예를 들어 10,000스텝 간격으로 50개 고정 시나리오를 평가하는 계획을 먼저 검토한다. 중단 기준은 사전 정의된 Validation의 정체/실패 진단이며 Test 성공률을 보고 연장하지 않는다. 최소·최대 예산과 평가 횟수를 사전에 함께 정한다.

## 실측 계산 비용과 추정의 한계

이번 CPU 한 스레드에서 수집+추론+업데이트를 측정했다. 중간 Validation/체크포인트/일부 저장은 아래 기본 비용에서 제외했다.

- A: 약 0.003313초/환경 스텝, 100,000스텝 단순 환산 약331초.
- B3: 약 0.004461초/스텝, 100,000스텝 약446초.
- C: 약 0.005800초/스텝, 100,000스텝 약580초.

같은 코드·PC로 위 Standard 250만스텝을 선형 환산하면 수집+업데이트 약3.3시간이다. Validation/Test/저장/중단 재개 비용을 포함하면 **4~8시간 정도의 임시 예산 범위**를 검토할 수 있다. 이는 실행 보장이 아니며 새 분포·프로토콜·인코더로 바뀌면 짧은 벤치마크를 다시 해야 한다. 향후 CAH 비용은 측정 전이므로 같다고 확정하지 않는다.

현재 MLP는 27,531 파라미터이고 CPU optimizer 비용은 수집 비용보다 작다. GPU보다 Python 환경·수집·로그 처리의 병목을 먼저 측정하는 것이 적절하다. 현재 CPU와 약31GiB RAM에서 작은 실험을 진행할 수 있고, GPU/서버 이전은 필수 전제 조건이 아니다. 병렬 환경을 추가한다면 난수·로그·에피소드 경계의 재현성을 다시 검사한다.

이번 출력은 원시 Test·진단·체크포인트를 포함해 약384MiB였다. 같은 저장 밀도를 가정하면 향후 알고리즘2개 × 학습 시드5개 × 계열5개 × 평가200개 = 10,000평가 에피소드의 원시 로그만 약5GiB 수준의 선형 추정이다. 기준선·Validation·학습 요약·checkpoint를 더해 10~20GiB 여유를 우선 확보하는 방안을 검토한다. 파일 크기는 로봇 수와 로그 방식에 따라 달라지며 확정 용량이 아니다.

## 본학습 전에 동결할 기록

- 시나리오 생성 버전과 Training/Validation/Test ID·시드·해시.
- 주 비교군과 중앙 참고군의 관측·통신·행동 차이.
- 책임 공백의 물리 판정, 평가 시간 창, 기한·미응답·검열 처리.
- Standard와 향후 CAH의 공통 보상 및 별도 민감도 설정.
- 네트워크/optimizer/GAE/mask/종료와 action 중재 규약.
- 학습 시드, 예산, Validation 주기, 선택·중단 규칙, 결정적/확률적 평가 모드.
- 의존성 잠금 파일, 코드 해시, checkpoint/resume 형식과 raw 로그 보존 규칙.
- 테스트 통과와 고정 예산의 짧은 재현 실행 결과.

Phase 3B-2A는 여기서 종료한다. 이 설계안은 다음 단계 승인을 대신하지 않는다.
