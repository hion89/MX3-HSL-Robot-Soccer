# Phase 4A 연구 문제 검증 및 규칙 기반 인계 결과

2026-11-19. 아래 수치는 실제 실행한 코드·저장한 원시 로그에서 측정했다. 가상의 예시 성능값이 아니다. 기존 Standard MAPPO 5개 선택 checkpoint와 보상 함수는 바꾸지 않았다. CAH-MAPPO와 재학습은 수행하지 않았다.

**판단: C. 현재 시뮬레이터의 현실성 및 평가 정의를 추가 검증해야 한다.** 인계 시간의 상충 관계는 재현했다. 그러나 기존 성능 포화와 드문 공백은 규칙으로 상당 부분 해결할 수 있었고, 신규 조건의 MAPPO 실패에는 학습 분포 이동이 섞였다. 이 결과만으로 학습 기반 인계 구조의 필요성을 입증할 수 없다.

## 1. 기존 Fixed와 MAPPO가 포화한 이유

기존 공통 400개 세계의 중앙 Fixed raw와 MAPPO 5시드 결정적 2,000회/확률적 6,000회를 다시 분석했다. 원시 파일 8,400개의 GT 지표를 기존 결과와 비교했다.

Fixed는 400/400에서 모든 작업을 완료했고 공백이 없었다. 구역 담당자 두 명이 계속 역할을 유지하면서 worker C/D가 작업 세 개를 순서대로 수행할 수 있었다. 따라서 **이 400개 세계에서 임무 성공과 구역 유지를 위해 역할 전환이 필수였던 세계는 0개**다. 이는 Fixed의 실제 실행이라는 가능성 증거이며 최적 스케줄을 계산했다는 뜻은 아니다.

1,200개 작업에서 발생→마감 창은 평균 20.03초, Fixed의 실제 완료 지연은 평균 8.1667초/최대 11초였다. 마감 여유는 평균 11.8633초, 최소 3초였다. 발생 순간 담당 worker의 이동 ETA는 평균 5.0508초였고 가까운 guard ETA는 평균 3.4658초였다. ETA는 다른 작업의 대기열을 무시하므로 실제 완료시간을 가능성 판단에 사용했다.

동적 작업 세 개가 동시에 활성인 구간은 총 12,800개 1초 구간 중 1,529개(11.9453%)였다. 순간 작업 수가 worker 수를 초과해도 마감 창 안에서 순차 처리가 가능했다. 작업을 즉시 동시에 수행해야 한다는 조건과 구분해야 한다. 실제 Fixed에서 guard의 작업 수행 때문에 구역 유지가 충돌한 경우는 없었다.

근거: `legacy/fixed_feasibility.json`, `legacy_paired_replay/travel_deadline_relationships.json`.

## 2. 평균이 숨겼던 24 구역-초 공백

확률적 6,000에피소드 중 67개(1.1167%)에서 공백이 발생했다. 이것을 6,000개 독립 학습 반복으로 해석하지 않는다. 독립 학습 시드는 5개다.

- 전체 에피소드 평균 공백 0.134 구역-초, 전체 상위5% 평균 2.68 구역-초, p95 0, 최대 24.
- 공백이 있었던 67개에 조건부로 평균 12초, p95 21초, 상위5%(4개) 평균 22.5초, 최대 24초.
- 이번 원본 기록에서는 구역별 연속 공백 구간도 67개였으며 위 조건부 분포와 같았다.

최악은 시드503, `benchmark-positions-0-00144-315442150a29`, 확률 반복2다. t=8에 guard A가 worker D도 요청하던 task1을 선택했다. 실행 중재의 ID 순서 때문에 A가 받아 D의 접근이 중단됐다. 후임 없이 base0를 비웠다. task1은 t=14에 완료됐지만 이후 로봇들은 이미 담당자가 있는 base1을 반복 요청했고 base0로 복귀하지 않았다. t=8~32의 24초가 공백이며 마지막까지 검열됐다. 그중 t=14~32의 18초, 즉 75%는 모든 작업이 끝난 이후였다.

같은 물리 세계에서 Fixed는 모든 작업을 공백 없이 완료했다. 따라서 이 사례는 필수 인계의 물리적 비용이라기보다 불필요한 guard 이탈, 중복 요청 중재, 사후 복귀 실패가 결합한 것이다.

67개 기존 공백 사례만 선별해 같은 checkpoint·샘플링 기저 시드7001·동일 반복으로 재현했다. 원형의 공백·작업 결과가 정확히 일치했다. READY 규칙을 붙이면 67개 모두 공백0/작업 성공100%였다. 적응 규칙은 1개에서 5 구역-초가 남았고 작업은 모두 성공했다. 기존 67개에서 실패했던 작업은 합계 5개였으며 READY에서는 모두 성공했다.

이는 **사후 선별 사례의 기전 검사**다. 기존에 공백이 없던 전체 사례의 부작용을 새로 전수 평가한 결과가 아니며, 전체 400개에 대한 무편향 개선율이나 미사용 Test 결과로 표현하지 않는다. 선택된 공백 사례에서 작업 응답은 시드별로 약 0.72~1.26초 느려졌다.

근거: `legacy/worst_gap.json`, `analysis_extended_v2/legacy_pooled_gaps.json`, `legacy_paired_replay/paired_results.json`.

## 3. 신규 시나리오와 가능성 검증

버전은 `phase4a-v1`이다. 2대·1구역·1작업과 4대·2구역·3작업을 함께 사용했다. 같은 split/team/index의 위치·속도는 A/B/C/위험/고장 계열 사이에 일치한다. 마감·위험·고장이라는 명시한 요인만 바꾼다. 각 로봇 용량은1이고 32초 평가를 유지한다.

guard는 속도1, 대체 worker는 0.45/0.5/0.55이며 같은 수평선에서 더 먼 곳에 있다. 실제 로봇의 체력·구동 성능 차이나 이미 먼 곳에 있는 지원 로봇을 단순화했다. 4대 사례의 다른 worker는 별도의 12초 작업과 후속 작업을 맡는다. 실제 축구에서의 12초 점유 빈도를 측정한 것은 아니다.

다음은 **신규 작업 발생(t=2) 이후 반응하여 준비를 시작하는 경우**의 구분이다.

- A: 역할을 유지한 worker의 직접 수행도 마감 이전이다.
- B: 느린 worker의 직접 수행은 늦지만, worker가 가까운 구역을 인수하고 빠른 담당자가 작업하면 기다려도 마감을 지킨다.
- C: 빠른 담당자의 즉시 전환은 성공하지만 후임 준비를 기다리는 실행은 마감을 넘는다.
- C_risk: C와 같은 시간 조건에서 기존 구역의 위험도8/대응 제한2초.
- R_risk: C와 같은 시간 조건에서 t=3에 위험도가1→8로 증가한다. 미래 위험 사건은 Actor와 실행기에 미리 주지 않는다.
- F_incumbent/F_successor: 각각 t=2 기존 담당자 고장/t=3 후임 고장이다. 절반은 t=10에 장치 복구, 나머지는 복구 사건이 없다.

기한은 비교 정책의 성능을 본 뒤 맞추지 않았다. 독립적인 fixed/immediate/ready 결정적 실행의 실제 완료시간으로 창을 정의하고 전 사례의 기대 관계를 확인했다. 기존 400개 환경과 결과는 변경하지 않았다. Validation 42개, 별도 진단84개이며 집합 사이 사건 스트림을 분리했다. 조건별 개수는 설계상의 균등 수이며 실제 경기의 발생 확률이 아니다. 균등 혼합 전체 평균으로 방법의 우열을 판정하지 않는다.

추가로 준비 시작0/2초와 출발2~29초를 바꾸는 제한된 스케줄 1,680개를 탐색했다. 2대 C 사례 6개 중 **1개는 t=0부터 후임을 미리 준비시키면 성공100%/공백0이 가능했다.** 반응 시작을2초로 제한하면 6개 모두 성공과 공백0을 동시에 달성하지 못했다. 따라서 C라는 이름을 ‘모든 가능한 시간 계획에서 불가피한 공백’으로 해석하면 안 된다. 이 탐색도 정해진 교대 순서만 조사하며 완전한 시간적 최적해가 아니다. 기존 Exact 역시 매 시점의 할당 비용 탐색일 뿐 시간적 최적해가 아니다.

이 발견은 인계 시작 시점·사전 배치·허용 준비 행동을 연구 문제 정의에 포함해야 한다는 근거다. 해당 사례를 불리하다는 이유로 제외하거나 수정하지 않았다.

근거: `design/feasibility.json`, `bounded_schedule_probe/results.json`.

## 4. 규칙 구현과 공정성

실행 게이트 두 종류를 분리했다. READY 규칙은 물리적으로 준비될 때까지 기다린다. 적응 규칙은 대기하면 마감 초과/바로 가면 준수, 작업과 구역의 우선순위 비율, 후임 ETA와 대응 제한시간을 함께 확인한다. 고장·위험 증가·요청 변경·작업 소멸에 대한 실패/취소 기록을 남긴다.

Validation의 후보 9개에서 사전 고정한 선택 순서를 적용한 결과 risk_ratio0.5/eta_budget4가 선택됐다. 진단 결과를 보고 바꾸지 않았다. Validation에서는 결정적 즉시 전환 요청을 입력해 실행 규칙만 비교했다. 저장 당시에는 후보 요약을 보관했고, 이후 동일한 결정적 실행을 378회 재현해 원래 후보 요약과 정확히 일치하는 raw도 별도 저장했다. 이를 원래 실행 때 저장한 trace라고 주장하지 않는다.

비교군은 기존 중앙 Fixed/Greedy/Exact/Handover, 로컬 Fixed/ETA, 별도의 실행 증인, Exact+두 실행 규칙, 기존 MAPPO5시드의 원형/READY/적응 규칙이다. MAPPO는 결정적1회/확률적2회씩 평가했다. 84개 공통 세계에서 41개 그룹, 총4,704에피소드, 약489.94초의 주 비교였다.

Actor는 기존146차원 패킷만 받고 Critic은 추론에 사용하지 않았다. 추가 게이트와 중앙 기준선은 특권적인 현재 팀 정보를 사용한다. 준비 중첩 명령도 원형 Standard 행동에 없었다. 따라서 MAPPO+규칙을 같은 MDP에서 재학습한 Standard 또는 CAH와 동일하다고 부르지 않는다. 원래 샘플 행동·log-probability는 유지하며 실행 변화 69,479건은 따로 기록했다.

## 5. 성공·공백·응답의 상충 관계

아래는 4대·3작업, 각 조건6개 세계다. 분모는 모두32초×2구역=64 구역-초다. task0은 이번에 대응해야 할 신규 작업이며, 전체 작업 성공률과 구분했다. 응답과 완료 지연은 task0 발생 기준이며 성공/응답 사례에 조건부다.

A:

- Fixed: 전체/신규 작업 성공100%, 공백0/64, 신규 응답9.50초·완료11.50초.
- Greedy: 성공100%, 공백8.667/64(CGR13.542%), 응답3.333초·완료5.333초.
- Exact: 성공100%, 공백4/64(CGR6.25%), 응답3.333초·완료5.333초.
- Exact+READY/적응: 성공100%, 공백0/64, 응답7.333초·완료9.333초.

B:

- Fixed: 전체 성공66.667%지만 신규 작업 성공0%, 공백0/64.
- Greedy/Exact: 전체·신규 성공100%, 각각 공백8.667/64와4/64.
- 기존 Handover 및 Exact+READY/적응: 전체·신규 성공100%, 공백0/64, 신규 응답7.333초·완료9.333초.

C:

- Fixed 및 Exact+READY: 전체 성공66.667%/신규 작업0%, 공백0/64. 실패한 신규 작업 완료시간을0초로 채우지 않는다.
- Greedy: 전체·신규 성공100%, 공백8.667/64, 응답3.333초.
- Exact/기존 Handover/Exact+적응: 전체·신규 성공100%, 공백4/64(CGR6.25%), 응답3.333초·완료5.333초.

즉시 전환은 C의 마감에 유리하고, 대기는 B의 구역 보호에 유리했다. A에서는 Fixed로도 충분했다. 구역을 끝까지 지킨 Fixed의0% 공백을 임무 성공으로 포장하면 B/C의 실패를 숨기게 된다.

고위험 C_risk에서 Exact+적응의 전체 성공률은77.778%/신규33.333%, 공백1.833구역-초였다. 무조건 대기는 신규 성공0%/공백0이었다. 위험 가중 CGR은 단순히1.833/64가 아니므로 원본 JSON의 위험 가중 분모와 함께 읽는다. 임의 위험 가중치가 실제 실점 확률이라는 근거는 없다.

기존 담당자 고장 조건에서 Exact+READY는 평균 구역 공백을16→4구역-초로 줄였지만 전체 성공100%→66.667%가 됐다. 구역을 대신 지킨 대가로 신규 작업을 놓쳤다. 이 값은 장치가 수리된 시간이 아니라 다른 로봇이 물리 커버를 회복한 시간/공백이다. 취소·실패·역할 변경·복구 검열의 전 수치는 조건별 CSV/JSON에 기록했다.

## 6. 기존 MAPPO와 규칙의 한계

새 4대 B/C에서 기존 MAPPO의 결정적·확률적 신규 task0 성공률은 5시드 모두0%, 전체 작업 성공률33.333%, 공백0이었다. 두 규칙을 붙여도 같은 결과였다. 이 규칙은 원래 정책이 선택하지 않은 작업을 발명해서 배정하지 않으므로, 잘못된 작업 선택 자체를 대신 해결할 수 없다.

새 4대 A에서도 결정적 전체·신규 작업 성공률은 시드 평균50%였고, 확률적 전체48.333%/신규36.667%였다. 공백0이었다. 따라서 B/C의 실패를 인계 문제에만 돌릴 수 없다. 쉬운 역할 유지 조건부터 기존 고정 checkpoint의 전이가 충분하지 않았다.

단일 요인 진단으로 기존 세계12개에서 checkpoint5개를 그대로 평가했다. 결정적/확률적 성공률 평균은 다음과 같다.

- 원래 조건100%/100%.
- worker 속도만1→0.5:95.556%/89.444%.
- task1 서비스 시간만2→12초:78.889%/87.222%.
- task1 발생만4→0초:100%/100%.
- 세 요인 결합:74.444%/70%.

## 8. 연구 판단과 남은 조건

이 자료는 ‘인계 비용이 존재한다’는 점을 뒷받침하지만 ‘새로운 학습 구조가 필요하다’는 점을 입증하지 못한다.

1. 기존400개에서는 역할 유지가 충분했고 알려진 공백 사례는 단순 READY 규칙으로 해결됐다.
2. 신규 반응형 B/C의 상충 관계는 단순 규칙으로 상당 부분 표현된다.
3. 신규 MAPPO 실패는 재학습하지 않은 분포 이동·작업 선택 실패와 혼합돼 있다.
4. 사전 준비를 허용하면 일부 C가 달라진다. 준비 행동의 가용 시점과 초기 배치 조건을 명시해야 한다.
5. 구역 위험도·대응 제한2/4초는 설계값이다. 상대 공격·공·가로채기·실점 모델, 실제 로봇 이동/회전 성능과 연결해 검증하지 않았다. 점 반경 안의 용량 매칭이라는 CGR을 실제 방어 성공과 동일시할 수 없다.

따라서 **C를 선택한다.** 기존 제한된 분포에서는 B에 가까운 증거가 있지만, 모든 주요 실전 조건에서 규칙이면 충분하다고 입증한 것도 아니다. 다음 승인 전에는 CAH-MAPPO나 추가 본학습을 진행하지 않는다. 후속 검토가 필요하다면 준비/초기배치 규약, 실제 위협과 대응 제한의 근거, 같은 정보·행동을 쓰는 비교 계약을 먼저 정리해야 한다. 이번 결과를 보고 보호 Holdout이나 알고리즘 구조를 변경하지 않았다.
