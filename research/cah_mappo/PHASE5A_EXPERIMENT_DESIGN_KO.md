# Phase 5A  역할 할당 비교 연구 실험 설계

2026-11-23. 본 문서는 미실행 설계다. 정책 성능을 새로 측정하거나 MAPPO를 재학습하지 않았다. 기존 연구 결과와 보호 Holdout은 보존한다.

## 1. 연구 질문과 주장 범위

실제 휴머노이드의 이동·회전·지연·위치 오차·통신·고장/복구 특성이 역할 할당의 작업 성공, 위협 대응, 책임 공백, 응답에 어떤 영향을 주는지 비교한다. 특정 방법의 우월성을 전제하지 않는다. 주효과와 조건×전략의 상충 관계를 분석하며 하나의 가중 종합점수로 우열을 정하지 않는다.

단계별 증거를 구분한다. 기존 추상 시뮬레이션 결과, 실측 파라미터로 보정한 전략 시뮬레이션, 독립 실물 재현은 서로 다른 실험이다. 한 대의 보행 성공을 다중 로봇 전략 검증으로, 보정에 사용한 궤적 재현을 독립 sim-to-real 검증으로 부르지 않는다.

## 2. 공통 과제와 역할 의미

초기 비교는2대/지속 책임 구역1개/동적 과제1개를 중심으로 하고, 물리·정보 계약을 검증한 뒤3~4대/복수 과제로 확장한다. 작업은 위치·발생·중요도·마감·성공 조건·점유 자원을 가진다. 로봇당 capacity1, 기존 책임 구역은 신규 작업 종료 후에도 유지한다. 담당자 이름과 실제 도착·가용 상태를 구분한다.

실물 첫 과제는 독립 GT로 관측 가능한 영역 방문·정지 유지/상대 방향 보기 등 contact 없는 작업을 우선한다. 실제 킥은 별도 안정성 승인·성공 기준이 필요하다. 제한 시간 안에 구역에 도달하는 과제, 공이 선을 통과하는 사건, 실제 공 차단/실점은 구분한다. 위협을 쓰지 않는 세계에서는 통과율은 N/A다.

현재 연구의 “task 할당/guard 전환”과 실제 HSL의 attacker/defender/goalkeeper·active_player는 자동으로 일치하지 않는다. 기존 ROS2의 역할 설정, 공 담당 결정, WalkToPose/GoToBallAndKick, walking/kick 제어권 양도를 매핑하는 후속 adapter가 필요하다. 기존 모델이 실물에서 이미 역할을 출력한다고 가정하지 않는다. 현재 Phase5B 제안은 계측까지이며 이 adapter 구현/배포는 포함하지 않는다.

## 3. 정보 조건과 비교군

### L: 로컬 관측 기준의 주 비교 계약

각 로봇은 자기 센서/허용된 지도·고정 초기 역할/실제 수신된 보고만 사용한다. 미래 사건·작업·타 로봇 GT·미도착 메시지·latent 물리 파라미터는 입력하지 않는다. 센서/캐시 age·slot/mask·관측 가능한 작업 후보의 정의를 고정한다. GT는 evaluator와 학습 시 Critic용이며 추론 Actor에 전달하지 않는다.

첫 frozen-transfer 비교에서 바로 재사용 가능한 것은 기존146/10 `LocalPolicy(local_fixed/local_eta)`와 Standard MAPPO다. **기존 중앙 Exact/RuleBasedHandover를 이름만 바꿔 이 그룹에 넣을 수 없다.**5개 방법의 완전한 L 비교를 위해서는 후속 단계에서 Local-Exact/Local-Handover 입력 adapter와 정보 감사가 필요하다.

후속 local 변형은 공통146차원 관측을 해석한 현재 알려진 작업·peer 상태만 사용한다. 미수신 타 로봇 할당/작업 진행/회전 능력은 unknown으로 남기거나 사전 공개한 보정 prior로만 추정한다. Exact는 이 공개 후보의 유효 할당을 탐색하되 자신의 출력만 실행 요청으로 내보낸다. 전역 실제 할당을 읽어 switching cost를 계산하지 않는다. Handover의 READY도 같은 fresh 관측으로 추정한 상태이며 GT READY와 구분한다. 진짜 ACK/새 역할 메시지를 도입하려면 통신·입력 계약을 별도 수정하고 모든 비교군의 접근 가능성을 다시 검증한다.

Local 변형은 기존 중앙 정책과 동일 실행 결과를 보장하지 않으므로 별도 버전으로 보고한다. 인터페이스를 손실 없이 맞출 수 없다면 L은 기존3방법의 동등 정보 비교로 제한하고 중앙2방법을 별도 참고군으로 보고한다.5개를 강제로 한 표의 동등 조건 순위로 만들지 않는다. 이 한계 해소 여부가 후속 비교 착수 gate다.

### R: 수신 팀 정보 기반 중앙 참고군

Fixed/Greedy/Exact/RuleBasedHandover는 현재 수신된 팀 보고의 공통 cache를 사용하는 배치를 별도로 검토한다. 실제 정보를 넘어선 숨은 상태를 쓰지 않도록 입력 출처를 audit한다. 분산 통신 결과를 모아 결정하는 중앙 배치의 정보 집합/전달 비용·결정 전파 지연을 기록한다. 각 Actor가 보는 입력보다 풍부하면 동등 비교가 아니므로 R 참고군으로 표시한다.

### O: 특권 오프라인 참고

현재 전체 GT 또는 미래를 아는 제한 스케줄은 물리 가능성 진단으로만 사용한다. 현재 GT 참고도 센서 기반 실행 정책과 다르다. 미래를 아는 탐색에서 실행 증인을 찾았다는 사실만으로 최적 상한을 계산했다고 부르지 않는다. 증인 부재를 불가능 증명으로 바꾸지 않는다.

## 4. 정책별 고정 사항

- Fixed Role: 초기 책임·공개된 지정 작업/순서 유지. 구조적으로 처리 불가능한 경우 성공0도 그대로 보고한다. 공백0만으로 승자로 삼지 않는다.
- Greedy/ETA: 같은 관측의 중요도/마감/예상 도달시간으로 선택. 보정 ETA의 정보와 uncertainty를 기록하고 GT 속도를 직접 참조하지 않는다.
- Exact Assignment + Switching Cost: capacity1 유효 할당을 전수 탐색한다. Hungarian·완전 시간 계획기로 부르지 않는다. 기존 비용2/50은 설계값이며 필요 변경은 Validation에서 별도 버전으로 고정한다. 내부 비용을 논문 평가 점수로 사용하지 않는다.
- Rule-Based Handover: 기존 담당·후임 후보·freshness/도착 추정·마감·위험에 따른 요청/유지/취소/조기 해제/고장 대체를 기록한다. READY-only와 적응 gate를 필요 시 별도 설정으로 두고 Validation에서 임계값을 정한다. Phase4C 사후 보완 규칙은 강한 개발 진단군이며 새 최종 자료에서 검증되지 않았다.
- Standard MAPPO: 기존5개 선택 checkpoint/146-64-64-10 Actor/141-64-64-1 Critic을 보존한다. 추론은 Actor만 사용하며 결정적·확률적 결과를 분리한다. 새 속도·잡음·통신·task/slot·control clock이 학습 분포와 얼마나 달라졌는지 기록한다. Frozen 결과를 새 환경에 학습한 MAPPO의 본질적 성능이라고 주장하지 않는다. 이번에는 학습하지 않는다.

모든 방법에 같은 좌표·실효 명령 cap·하위 보행/킥 모델·중재·안전 gate를 적용하는 것을 원칙으로 한다. gate를 특정 정책에만 붙이면 독립 조건으로 표시한다. 요청 행동과 실행 행동을 각각 남기고, MAPPO sample/log-probability를 중재 결과로 갈아 끼우지 않는다. 교체/준비 요청을 허용하지 않는 행동 공간과 허용하는 공간도 한 조건으로 혼합하지 않는다.

## 5. 공통 시나리오와 요인

기존 집합은 진단 참고로 보존하고 새 `empirical_mx3_v1`의 Training/Validation/평가 개발 집합을 별도로 설계한다. 생성기는 정책 호출 전 초기 상태·작업·외생 사건을 만들고 scenario ID/config/hash를 보관한다. 같은 world에서 정책만 교체하고, 정책 난수는 외생 RNG와 분리한다. 실제 센서 가시성은 같은 모델/실제 궤적에서 계산하므로 정책별 관측이 달라질 수 있다.

최소 조건 사다리는 다음과 같다.

1. 역할 전환 없이 가능한 과제. Fixed로 충분한 상황을 남긴다.
2. 역할 전환이 필요하지만 준비를 기다릴 마감 여유가 있는 과제.
3. 긴급 마감과 기존 구역 대응이 충돌하는 과제. 물리 가능성 하한/성공 증인/미확정을 표시한다.
4. 동일 과제의 실측 이동 속도·회전·응답 지연 변화. 바닥/건강 조건을 실제 수집한 범위로 구분한다.
5. 자기위치·공 관측 오차/age·동기 불확실성, 통신 지연/유실/상태 발견 차이.
6. 기존 담당 또는 후임의 가용성 중단/복귀, 이후 실제 서비스 재개. 정책 자체 낙상과 동일 외생 중단을 분리한다.

처음에는 한 요인씩 바꾸고, 데이터가 지지한 뒤 이동×통신·위치오차×마감 등 제한된 상호작용을 추가한다. 임의의 전 요인 grid와 대규모 학습을 자동 시작하지 않는다. 실물에서 측정하지 않은 장애를 “실측 강건성”으로 부르지 않는다. 현재120개 세계의 빈도를 실제 경기 발생 빈도로 가정하지 않는다.

공정성은 모든 전략에 같은 외생 세계/센서·전달 규칙을 제공한다는 뜻이다. 같은 실물 실험을 완전히 같은 배터리·공 궤적으로 반복할 수 없으므로 session/floor/실효 설정으로 block을 만들고 순서를 균형화한다. 실제 입력·GT가 달라졌으면 다른 trial로 남기고 완전 대응 실험이라고 과장하지 않는다.

## 6. 지표와 성공 판정

지표는 정책 보상과 분리한 GT/원시 event에서 계산한다. 성공/실패 경계·측정 오차·누락 처리·평가창을 실험 전에 고정한다.

- Task Success Rate: 발생한 전체 과제 중 GT 조건을 마감 내 충족한 비율. 작업 단위 비율과 모든 작업 성공 에피소드 비율을 각각 보고한다. 안전 중단·미응답을 누락하지 않는다.
- Deadline Miss Rate/준수율: 마감까지 실패·미응답 포함. 성공률과 사실상 같은 조건이면 중복된 새로운 성과처럼 해석하지 않는다.
- Threat Pass Rate: 명시된 위협 사건/유효 관측 노출 중 실제 선/구역 통과 비율. 추상 sim event, contact 없는 실물 응답 과제, 실제 공 차단을 구분하고 실점률이라고 부르지 않는다.
- 실제 대응 가능성 공백: GT 위치·현재 작업 용량·보정 이동/회전/대기 모델로 대응 예산 내 가능한 매칭이 없는 시간. **실물에서도 반사실적 ETA를 포함한 모델 기반 추정**이다. 무오차 GT 지표라고 부르지 않는다. 명목/보수적 ETA 및 불확실 구간을 병기하고 실제 구역 도달/위협 결과와 대조한다.
- 지점 서비스 공백/명시 담당자 공백: GT로 구역에 가용 로봇이 실제 있는지와 명시 owner가 있는지를 따로 적분한다. 작업 중에는 capacity를 중복 사용하지 않는다.
- legacy CGR/위협 가중 공백/작업 후 공백: 기존 정의·버전 보존. 가중 분자/가중 분모와 무가중 구역-초를 함께 기록한다.2대1구역32초면32, 4대2구역이면64이지만 위험도가 변한 legacy 분모는 다를 수 있다. 작업 종료로 책임 평가를 조기 종료하지 않는다.
- Response/Completion Time: 발생→실제 대응 시작/GT 완료. 성공 조건부 평균과 미응답·마감 실패 비율을 함께 보고한다. 전체 완료시간은 모든 작업 성공한 경우에만 정의하고 검열을 표시한다.
- Role Switching Count: 요청/승인된 책임·작업 전환과 실제 HSL 역할 라벨 변화를 각각 기록한다. 걷기↔킥 저수준 러너 전환을 역할 변경으로 합산하지 않는다. 중복 요청·수락, 인계 취소/고장·지연도 보조 지표다.
- Recovery Time: 장치 기상 시간, 제어 가용 신호, 독립 GT 서비스 복귀 시간을 분리한다. 실패·관측 종료는 검열이며 무한 실패를 성공 시간 평균에서 삭제하지 않는다. 공통 horizon의 미복구율/제한 평균을 함께 검토한다.

점유반경·위협 도달·상태 전이 시점은 물리 dt와 제어 clock의 영향을 받는다. 새 경계 사례는0.125/0.0625초 또는 측정 분해능에 맞는 추가 해상도로 민감도를 검사할 계획이며 이번에는 실행하지 않는다. GT가 없는 구간을 공백0으로 채우지 않고 관측 가능 시간과 상하한을 보고한다.

## 7. 통계·반복·계산 비용

초기 실물 계획의3~5회는 계측 예비용이다. 본 측정 수는 trial/session 간 분산과 사전 정한 오차 허용치·검출할 차이·계산/열 예산으로 결정한다. frame/packet/tick을 서로 독립인 로봇 실험 수로 세지 않는다. 한 대 장비에서는 로봇 간 일반화 CI를 만들지 않는다.

시뮬레이션은 동일 world의 정책 차이를 대응 비교한다. 기존 MAPPO의 독립 반복 단위는 학습 seed5개이며, 여러 sampling repeat/episode는 그 안의 반복이다. 먼저 seed별 성공·공백·응답·분포를 보고하고 seed 간 평균/중앙/범위·CI를 따로 제시한다. 시나리오 대응 불확실성과 학습 seed 불확실성을 분리한다. 규칙 정책에 임의의5개 복제 결과를 만들어 독립 학습 반복으로 세지 않는다.

실물은 floor/day/battery·건강/session/robot 단위의 block과 trial을 보존한다. 가능한 경우 대응 차이의 CI, 이항 성공률의 구간, cluster bootstrap 또는 적절한 계층 분석을 검토한다. 유효 군집 수가 적으면 CI의 불안정성과 기술통계 한계를 명시한다. 성공한 trial만의 짧은 응답시간으로 유리함을 주장하지 않는다.

주 분석은 작업 성공·위협 통과와 책임 공백·응답시간의 상충 관계다. 효과 크기와 불확실성을 우선하며 여러 조건/정책의 유의성 검정을 하려면 대조·family와 다중 비교 처리를 사전 고정한다. 결과를 보고 유리한 threshold·종합점수·표본 제외·checkpoint를 선택하지 않는다. 차이가 없다는 관측을 동등성 증명으로 바꾸려면 별도의 사전 동등성 한계와 검정력이 필요하다.

계산 비용은 기존 CPU inference/평가 코드를 재사용하되 Phase5C의 새 모델/step 비용을 예비 측정한 뒤 정한다. 이번 단계에서 추가 시드·학습·최종400 평가를 시작하지 않는다. 새로운 본학습이 필요하면 데이터·보상·예산·환경·seed 계획을 별도로 승인받는다.

## 8. 보정·모델 선택·최종 평가 분리

실물 예비/보정(C_fit/C_dev)/독립 물리 검증(C_check), 전략 Training/Validation, 최종 평가를 용도와 session 단위로 분리한다. 같은 영상의 frame 분리로 정보 누출을 피했다고 주장하지 않는다. 기존에 분석한400 benchmark와 개발120세계는 계속 개발/진단용이다.

기존 봉인 Holdout400개는 열람하지 않는다. 그 생성 계약과 새 실측 분포가 달라질 가능성만 문서 수준에서 검토한다. 기존 test를 보고 새 정책을 맞추거나 오래된 Holdout을 새 실물 환경의 대표 데이터로 선언하지 않는다. 새 final set은 보정/정책/입력·행동/평가창·선택 규칙을 모두 고정한 뒤 별도 버전으로 만든다. 최종 결과를 보고 수정하면 그 결과는 개발 자료로 격하하고 독립 최종 평가를 다시 준비한다.

## 9. 다음 단계로 넘어갈 조건

Phase5B는 독립 GT/시각/안전·장비와 실제 성능 자료 확보다. Phase5C는 별도 승인 후 보정 버전/공통 adapter/정보 감사와 평가 재계산 검증이다. 이후 frozen MAPPO 전이·규칙 비교, 필요 시 별도 승인된 재학습, 마지막으로 제한 실물 전략 비교를 진행한다.

정확한 task·정보·행동 의미가 맞지 않거나 GT 오차가 비교 효과보다 크면 해당 비교를 보류한다. 모든 주요 조건에서 단순 전략이 충분하면 알고리즘 우위 대신 적용 범위·실패 조건·계산/통신 비용을 보고한다. 이번 단계에서 실물 배포·새 코드·새 학습은 하지 않는다.
