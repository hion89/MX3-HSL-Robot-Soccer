# Phase 3B-2B Standard MAPPO 통제 실험 규약

2026-11-19. 수치 설정은 학습 전에 `phase3b2b_outputs/main_v1/frozen_plan.json`, `pretraining_freeze.json`, `source_manifest.json`으로 고정했다. 이 문서는 그 규약을 설명한다. 최종 보호 Holdout 400개는 열람하거나 평가하지 않는다. CAH-MAPPO는 구현하지 않는다.

## 해결된 문제와 이번 범위

이전 진단에서 작업 슬롯을 바꾸면 실패하는 실제 작업도 바뀌었으며 ID 변환 오류와 학습 슬롯 편향을 구분했다. 정상 정보 전달에서는 같은 MLP로4대·3작업 완료가 가능했지만, 독립 학습 시드 반복·다양한 물리 조건·확률적 실행의 안정성은 본격 검증하지 않았다. 관측 제한·지연·고장 조건의 정보 부재 문제는 해결되지 않았고 이번 주 실험에서 제외한다.

이번 반복은 이전 checkpoint를 공유해 이어 학습하지 않는다. 신경망과 optimizer를 각 시드에서 새로 초기화한다. 주 기준선은 일반 슬롯 배치이며 순열 증강을 자동 적용하지 않는다. 슬롯 변경은 학습 후 별도 진단이다.

## 환경

- 로봇4대, 각 용량1, 이동속도1m/s, 회전속도π rad/s. 고장·복구·감속 사건 없음.
- 책임 구역2개, 위치(0,+1.5)/(0,-1.5), 우선순위 각각1, 처음부터32초 내내 활성.
- 초기 역할 A/B guard, C/D worker. guard의 초기 위치 오차 ±0.05m, worker 초기 위치는(-2.5,±1.5)에서 각 축 ±0.75m. 초기 heading은 ±0.2rad.
- 동적 작업의 기준 위치(3,1)/(3,0)/(3,-1)에서 각 축 ±0.75m.
- 학습 작업 수1/2/3개를 확률0.2/0.2/0.6으로 생성. 주 평가에는 항상3개다.
- 작업 발생2/4/6초, 서비스2초, 기한20/24/28초 중 선택. 작업 중요도1/2/4.
- 평가 계열 `positions`는 중요도2·기한24초 고정, `conditions`는 중요도·기한도 랜덤화한다.
- 센서 반경100m, 잡음0, 무선 지연0, 메시지 손실 없음. 해당 제한 공간에서는 모든 현재 작업을 정상적으로 센서 관측한다. 아직 발생하지 않은 작업은 관측·Actor 입력에 포함하지 않는다.
- peer 패킷에는 위치·heading·속도·가동 여부 등이 있지만 다른 로봇의 실제 할당이나 전역 작업 owner 정보를 직접 제공하지 않는다.

이 환경은 추상적인 2D 이동·할당 환경이며 실물 접촉·보행·킥 모델이 아니다. 작업 중요도가 완료 보상을 직접 곱하는 구조로 바꾸지 않았다. 중요도는 기존 관측·대기 비용·기준선의 할당 비용에 반영되는 현재 정의 그대로다.

## 상태·행동·알고리즘

- 공유 Actor:146→64→64→10, Tanh, 14,218 파라미터.
- 별도 중앙 Critic:141→64→64→1, Tanh, 13,313 파라미터.
- Feed-forward Standard MAPPO. RNN, PopArt/ValueNorm, 새로운 인계 학습 구조 없음.
- 로봇4개·작업8개 고정 패딩. 행동0=해제/대기, 1=유지, 2~9=로컬 알려진 작업 슬롯0~7 선택.
- NOOP는 항상 남는다. 알려지지 않았거나 stale/inactive인 작업은 mask로 제외한다. 고장·패딩 에이전트 손실 제외 규약은 기존 구현을 유지하며 주 환경에서는4대 모두 가동한다.
- Actor는 자신의 허용 관측 패킷만 입력받는다. Critic의 상태나 privileged infos는 추론 함수로 전달하지 않는다.
- 중복 할당 중재는 공통 환경 전이다. 실제 샘플링한 행동·log-probability·mask를 저장하고 실행 결과를 별도 기록한다.
- 팀 보상당 Critic 표본 하나/환경 스텝. 에이전트 수만큼 복제해 value loss를 부풀리지 않는다.

PPO 설정은 gamma0.99, GAE lambda0.95, clip0.2, entropy0.01, value coefficient0.5, Adam lr0.0003/eps1e-5, gradient norm0.5다. rollout256, epochs4, minibatch64 환경 스텝, 활성 에이전트만의 advantage normalization을 사용한다. 네트워크 가중치는 float32, 분포 감사용 Categorical 계산은 float64다. 기존 Phase 3B-1 update/GAE 코드를 재사용한다.

보상은 기존 `phase3a/rewards.py` 그대로다.

```text
r = progress + 10*completion + response + 10*failure
    + waiting + 2*coverage + 0.1*switching
```

실패·대기·공백·전환 항 자체가 음수다. 진행/완료/대응/실패는 고정 작업 슬롯8로 정규화한다. 공백은 물리적 커버가 없는 구역의 우선순위 비율×dt/32, 전환은 기존의 비어 있지 않은 할당을 바꾼 횟수/로봇 수다. 보상과 평가 지표는 별도 함수로 계산한다. 미래 CAH 비교에서도 이 설정을 그대로 보존하거나 변경 요인을 명시해야 한다.

## 종료와 평가 분모

모든 주 평가는32초로 고정하고 작업 완료 뒤에도 책임 구역을 평가한다. 외부 시간 제한이므로 `truncated=True`, bootstrap1, continuation0이다. reset 전 마지막 상태 가치로 bootstrap하며 에피소드 경계를 넘어 GAE를 이어 붙이지 않는다. 임무의 정상 종료로 다시 정의하는 다른 실험과 혼합하지 않는다.

물리 커버는 가동 여부·구역 반경·현재 작업·용량1을 만족하는 매칭으로 계산한다. 담당자 이름만으로 커버로 세지 않는다. 구역별 공백을 합산하므로 두 구역이 동시에1초 비면2 구역-초다.

평가 대상은32초×구역2개=64 구역-초이고 위험 가중 분모도64다. CGR과 실제 공백 구역-초, 평가 구역 시간을 함께 보고한다. 다른 평가기간의 비율을 직접 비교하지 않는다.

## 독립 반복·예산·선택

독립 학습 시드는101/211/307/401/503이다. 초기 가중치·Actor 샘플링·shuffle RNG가 다르고 학습 사건 스트림도 서로 겹치지 않는다. 평가는 모든 모델이 같은 시나리오를 공유한다.

기존 TrainConfig의 `environment_seed`는 호환 필드이며 새 생성기에는 사용하지 않는다. 실제 사건 시드는 각 스트림의 생성 규칙, manifest와 훈련 trace의 scenario ID로 재현한다.

각 시드100,352스텝, 총501,760스텝으로 고정한다. 8,192스텝 간격과 마지막에 checkpoint/Validation을 저장한다. Validation은 두 계열 각각16개, 총32개 물리 시나리오를 결정적·확률적 모드로 평가한다. 선택은 다음 순서다.

1. 두 모드 중 낮은 작업 성공률 최대화.
2. 두 모드 평균 성공률 최대화.
3. 두 모드 중 더 큰 CGR 최소화.
4. 평균 제한 응답시간 최소화.

이는 checkpoint 선택 순서이며 논문상의 단일 종합 성능 점수가 아니다. Return으로 알고리즘의 우열을 정하지 않는다. 이미 확인한 benchmark/Test 결과를 보고 구조·보상·선택 규칙을 다시 바꾸지 않는다.

5개 모델의 선택을 모두 동결한 뒤 주 benchmark를 실행한다. 새 generator는 Training/Validation/benchmark 사건 시드 구간을 분리한다. 기존 보호 Holdout과 다른 비최종 공통 benchmark다. 기존 Test를 새로운 미사용 최종 평가로 부르지 않는다.

## 계산 비용 사전 확인

별도 시드999의512스텝과 Validation 일부에서 비용만 측정했다. 모델 선택이나 본실험 반복에는 포함하지 않는다.

- 약0.004984초/학습 스텝.
- 평가/압축 raw 저장 약0.1767초/에피소드, 압축 raw 약94,415 bytes/에피소드.
- 학습·검증·예정 평가 전체 직렬 실행 약5,413초, 약90분의 선형 추정.
- 출력 약2.14GiB 추정. 측정 시 디스크 여유 약321GiB.
- 최대5개 로컬 작업을 각 CPU1스레드로 병렬 실행한다. 실제 시간은 추정과 별도로 보고한다.

이 예산은 기존8시간/20GiB 계획 범위를 넘지 않는다. 예산을 늘려 성능을 맞추지 않는다. 새 패키지 설치나 GPU/원격 서버는 사용하지 않는다.

체크포인트는 PPO 업데이트가 끝난32초 에피소드 경계에서만 저장한다. 네트워크·optimizer·RNG·사건 커서와 다음 초기 상태를 저장하고 재구성한 상태와 비교한다. 같은 코드/설정에서 저장 후 재개한 다음 rollout과 업데이트가 중단 없는 실행과 정확히 같음을 테스트했다. 임의 중간 시점 resume를 지원한다고 주장하지 않는다.

## 평가와 관측 공정성

주 평가는 계열별200개, 총400개 물리 시나리오다. 시드별 결정적1회, 확률적3회/시나리오를 실행한다. 같은 시나리오의 반복·슬롯 변형을 독립 학습 반복으로 세지 않는다.

로컬 비교군은 `local_fixed`, `local_eta`이며 같은 Actor 관측 패킷을 받는다. 기존 중앙 `fixed/greedy/exact/handover`는 그대로 별도 참고군으로 둔다. 중앙에는 현재 할당·owner·fixed_owner 등 추가 정보가 있다. 중앙 Handover는 기존 준비 행동도 사용한다. 따라서 중앙군을 동등 관측·행동 비교군이나 수학적 성능 상한이라고 표현하지 않는다. Exact는 소규모 완전 탐색이며 Hungarian이 아니다. 비용은 switching2, unassigned50이다.

중앙군의 Episode Return도 같은 보상 항으로 raw 상태/이벤트에서 재구성한다. 이것은 평가용 보상 진단이며 학습기나 평가 지표를 바꾸지 않는다. 같은 스크립트의 Native 환경 실행과 보상이 일치함을 테스트했다.

슬롯 진단은 `conditions`의 사전 지정 첫32개 물리 시나리오에서 여섯 순열을 평가한다. 원래 슬롯 결과는 주 평가의 반복0을 재사용하고 나머지 다섯 순열만 추가 실행한다. 두 모드를 각각 기록하며, 이 추가 진단의 확률적 반복 수는1이다. 작업별 선택 빈도·완료·기한 초과·원래 배치와의 대응 차이를 보고한다. 결과에 맞춰 자동으로 순열 증강 학습으로 전환하지 않는다.

## 통계·재현성

독립 반복 단위는 학습 시드5개다. 평균·중앙값·표준편차·범위와 자유도4의 Student t 95% 구간을 사용한다. 구간은 고정 benchmark 조건의 시드 변동에 대한 서술적 구간이며 다중 비교를 보정한 유의성 판정이 아니다. 비율의 근사 구간은 물리 범위를 벗어날 수 있어 임의로 잘라내지 않는다.

정책 간에는 같은 시나리오 ID를 대응시켜 시드별 평균 차이를 구하고, 그 다섯 차이의 변동을 별도로 보고한다. 조건부 응답시간/인계 공백처럼 정의되지 않는 값은0으로 바꾸지 않고 관측 쌍 수를 함께 기록한다. 인계가 없으면 Handover Gap Duration은N/A이며 인계 횟수0을 따로 표시한다.

기존 Handover Gap은 책임 해제부터 지정 후임의 준비까지의 초기 시간이며, 후임 미지정 때는 실제 커버 회복까지다. 다음 인계/평가 종료로 검열된 값은 하한이며 실제 물리 공백과 항상 같지 않다. 원시 로그의 검열 여부와 물리 공백 합집합 시간을 함께 보고한다. 무인계 사례를0초 인계라고 채우지 않는다.

Duplicate Assignment Rate는 의도되지 않은 실제 중복 할당 구간/활성 작업-시간이다. 의도한 준비 중첩은 제외한다. 공통 중재가 실제 중복을 막으므로, 별도의 중복 요청 비율도 보고한다. Role Switching Count는 구역/작업 종류 전환이며 같은 종류 안의 할당 변경 횟수도 별도 기록한다. 보상의 switching항은 기존 비어 있지 않은 할당의 변경에 대한 비용으로, 평가의 역할 전환 횟수와 동일한 식은 아니다.

raw는 표준 라이브러리 gzip JSONL로 저장한다. 전체 평가 raw와 훈련 의사결정, 모든 학습 에피소드 요약, 학습·Validation 곡선, 설정·시드·코드 해시·버전·checkpoint를 보존한다. 보호 Holdout 파일은 내용 대신 파일 크기·수정 시각 등의 메타데이터만 확인한다.
