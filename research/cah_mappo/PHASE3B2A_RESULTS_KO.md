# Phase 3B-2A 실제 결과와 실패 원인 분석

측정일 2026-11-18. 아래 값은 실제 CPU 실행 결과다. 추정 자원과 미실행 계획은 `PHASE3B2B_PLAN_KO.md`로 분리했다. 단일 학습 시드의 예비 실험이며 논문 성능 검증이 아니다.

## 완료 범위

랜덤화된 Training/Validation/Test, 동일 외생 사건 비교, 로컬 관측 기준선, 별도 중앙 참고군, 보상 계수 두 설정, 로봇 2~4대/작업 수 변화 검증을 구현했다. 실제 학습은 A 두 설정, B3와 C의 순서로 총 22,528스텝 수행했다. D는 난이도만 평가했다. CAH-MAPPO, 새로운 인계 학습 구조, 대규모 다중 시드 본학습은 구현·실행하지 않았다.

전용 환경은 기존 승인된 Python 3.12.14 / PyTorch 2.7.0+cpu / NumPy 1.26.4다. 새 라이브러리 설치, 원격 접속, 실물 구동, Git 커밋·푸시는 없었다.

## 기존 64~66% 책임 공백의 분석

기존 시드 7·11 최종 확률적 평가 각 20개 원시 로그를 읽었다. 원인 하나로 단정하지 않고 다음을 구분했다.

**보상 규모:** 시드 7의 평균 보상 기여는 완료 +1.25, 진행 +0.125, 대응 +0.125, 공백 -0.475, 전환 -0.130, 대기 -0.00698이었다. 시드 11은 완료/진행/대응이 같고 공백 -0.47917, 전환 -0.1325, 대기 -0.00766이었다. 완료 보상이 실제 관측 공백 비용보다 컸다. 기존 24초 설정에서는 공백 1초의 기본 페널티가 2/24≈0.0833이며 완료 항 1.25는 약 15초 공백 비용과 같다. 이것은 유인 구조의 증거지만 학습 결과의 유일한 원인이라는 뜻은 아니다.

**위험도 관측:** Actor 벡터에는 알려진 구역의 우선순위/10이 들어 있다. 기존 궤적에서 실제 입력된 구역 우선순위는 모두 1이었다. 따라서 위험도가 바뀔 때 다르게 행동하도록 학습한 증거가 없다. 또 구역 한 개의 공백 비율은 우선순위로 정규화되어 절대 위험도 1→8이 공백 페널티를 바꾸지 않는다. 이 성질을 실제 전이 테스트로 확인했다. 구역이 여러 개면 상대 우선순위는 영향을 준다. 위험도는 현재 추상적 가중치이며 실제 손상 발생 모델은 아니다.

**행동 표현:** 유지/해제/알려진 작업 선택만 있다. 후임이 기존 담당자와 동시에 구역으로 이동하는 준비 행동은 없다. 기존 담당자가 남아 있을 때 후임이 같은 구역을 선택하면 중복 할당 중재가 거부하여 이동하지 못함을 테스트했다. Standard가 구역을 유지하면서 먼 B를 새 작업에 보낼 수는 있지만, A를 작업에 먼저 보내면서 B를 준비시키는 인계를 학습할 수 있는 표현은 아니다.

**분모와 물리 판정:** 기존 시드 7은 평균 8.7초 중 5.7초, 시드 11은 평균 9.35초 중 5.75초의 구역 공백이었다. 개별 비율 평균이 65.99%, 63.61%였다. 작업 종료가 빠를수록 에피소드가 짧아져 분모도 작아졌다. 기존 로그의 관측되지 않은 나머지 24초 구간을 임의로 커버 상태라고 채울 수 없다. 24초 공통 창의 공백 비율은 저장 로그만으로 시드 7에서 23.75~87.50%, 시드 11에서 23.96~85.00% 범위만 알 수 있다.

물리 커버는 가동 여부, 거리, 용량·현재 작업을 고려하므로 이름만 지정한 담당자를 커버로 오인하지 않는다. 다만 실제 자세·충돌·반응 시간은 포함하지 않은 2D 대응 가능성의 대용 지표다. 새 실험에서는 같은 평가기로 32초 공통 창을 사용한다.

**역할 변경과 중재:** 기존 평균 역할 전환은 2.2회·1.9회였다. 극단적인 역할 반복만으로 전체 현상을 설명하기는 어렵다. 할당 변경은 5.8회·5.45회, 중복 요청 비율은 17.89%·33.53%였다. 할당 변경에는 정상 작업 종료에 따른 해제도 포함되므로 전부 불필요하다고 세지 않는다. 중재 의존과 일부 비효율적 변경의 증거는 있다.

**고정 시나리오 과적합:** 기존 체크포인트의 재평가 결과, 새 A의 랜덤 위치에서도 성공률 100%였다. 따라서 작은 위치 변화 자체에 실패한 것은 아니다. 반면 두 번째 구역이 추가된 C에서는 0%였고 모든 요청이 구역을 향했다. 단일 작업 위치 과적합보다는 구역·작업 슬롯 구성의 변화에 취약한 증거가 더 명확하다. 구조/분포 변화가 함께 있으므로 하나의 원인으로 완전히 분리된 인과 실험은 아니다.

위 집계는 `pilot_v1/phase3b1_diagnostics.json`에 저장했다.

## 실험 분리와 통제

단계별 Training 24개, Validation 8개, Test 12개다. 사건 생성 시드는 세 집합 간 겹치지 않는다. 학습 시드는 7 하나로, 독립 학습 반복 수는 **1**이다. Test 12개를 독립 학습 12회라고 해석하지 않는다.

학습 전에 `predeclared_plan.json`을 만들었다. 기본 보상과 coverage=8은 같은 초기 신경망·시나리오·스텝 예산을 썼다. 1,024스텝 간격의 Validation 결정적 평가에서 성공률 → 공백 → 제한 응답시간의 순서로 checkpoint를 선택했다. 모든 선택을 `selection_freeze.json`으로 고정한 뒤 Test를 평가했다. Test를 보고 재학습하거나 보상을 변경하지 않았다.

추론은 Actor 패킷만 받는다. 기존 중앙 Fixed/Greedy/Exact/Handover는 그대로 두고 추가 정보를 가진 참고군으로 별도 표시했다. 특히 중앙 Handover에는 Standard에 없는 기존 준비 행동도 있어, 동일 관측·행동 조건의 알고리즘 비교로 사용하면 안 된다. 중앙 Exact는 모든 유효 소규모 할당을 열거하며 Hungarian 구현이 아니다.

## 슬롯 및 D 실패 진단

기존 3B-1과 새 A 체크포인트를 옮겨 평가하면 A/B2/B3의 결정적 성공률은 100%, C는 0%였다. C에서 기존 정책의 1,536개 로봇-스텝 요청은 모두 구역을 향했다. 작업이 보이는 1,228개 로봇-스텝에서도 작업을 선택하지 않았다. 주로 행동 3, 즉 로컬 슬롯 1을 선택했다. 예전에는 그 슬롯이 작업이었고 C에서는 두 번째 구역이다. 코드의 ID 변환은 정확했으며, 학습된 flat MLP가 슬롯에 의존한다는 해석과 일치한다.

C를 학습한 결정적 정책은 task0와 task1을 각 12회 완료했지만 task2는 한 번도 완료하지 않았다. 세 번째 작업 슬롯 대응 부족이 구체적으로 남아 있다. 전체 평균만 보면 숨겨지는 문제다.

D의 A 전이 정책은 36개 작업 중 27개, local_fixed는 25개 작업을 해당 시험 궤적에서 끝까지 관측하지 못했다. 현재 행동은 알려진 작업/구역 선택뿐이며 미지의 영역을 탐색하는 자유 이동 목표는 없다. 해당 궤적에서 미관측이었다고 해서 모든 정책에 절대 발견 불가능하다고 단정하지 않는다. 다만 작업의 발견 가능 조건과 탐색·통지 규칙을 확인하지 않고 학습량만 늘리는 것은 부적절하다.

이는 `posthoc_v1/diagnostics.json`에 저장한 사후 기술 분석이다. 모델 선택이나 추가 학습에는 사용하지 않았다.

## 분모와 재학습 효과를 구분한 보조 비교

이전 3B-1 체크포인트를 같은 A Test/32초 창/같은 확률적 평가 규칙으로 재평가했다. 성공률 100%, 공백 14.583%, 응답 4.25초였다. 새 A/2 선택 후보도 성공률 100%, 공백 14.583%다.

따라서 ‘기존 66%→새 14.6%’를 재학습 개선으로 보고하지 않는다. 이전 종료 규칙·초기 조건·평가 난수와 이번 규칙이 다르다. 새 학습이 작동함은 확인했지만 이 조건에서 이전 모델보다 우수함은 확인하지 못했다.

## 저장물과 남은 문제

각 run의 CSV/JSON, 전체 Validation 결과, `A_reward_sensitivity_labeled.svg`, `validation_curves.svg`에 학습·검증 곡선을 저장했다. 원시 로그에는 응답, 실패, 완료, 역할·할당 변경과 중복 요청이 있다. 실행 중재가 실제 중복 수행을 방지하지만 MAPPO의 중복 요청은 여전히 많아 중재에 의존한다.
