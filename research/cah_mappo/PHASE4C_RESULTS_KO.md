# Phase 4C 연구 문제 타당성 검증 결과

2026-11-20. **최종 권고는 C: 기존 구현을 활용한 실증 비교 연구로 범위를 변경한다.** CAH-MAPPO 개발과 재학습을 계속 보류한다. 이번의 C는 앞 단계의 “현실성이 더 필요해 미확정”이라는 뜻이 아니라, 실측 제약과 기존 방법 비교를 연구의 중심으로 정하자는 결정이다. 근거와 후속 범위는 `RESEARCH_DIRECTION_DECISION_KO.md`에 정리했다.

아래 수치는 저장된 코드·원시 로그를 실제 실행/재계산한 값이다. 실물 성능으로 추정해 작성한 숫자나 가상의 예시 성능은 없다. 실측이 없는 항목과 이후 준비 계획은 따로 표시한다.

이번 판단에 사용한 문서는 각 단계의 `RESULTS_KO.md` 계열과 실제 `phase2/{model,engine,policies,metrics}.py`, `phase3a/perception.py`, Phase3B 학습/평가, `phase4b/{engine,metrics,policies,planning,scenarios}.py`, 보완 SensorActor/고장 규칙이다. 새 실험은 기존 엔진·보상·가중치를 바꾸지 않고 조합했다.

## 4. 실제 정보만 쓰는 비학습 진단 결과

첫 `risk_directed_swap`은 관측 위협에 맞춰 조용한 구역의 guard를 빌려온다. 이때 이미 수행하려던 다른 작업의 worker를 빈 구역으로 빼앗는 간섭이 발생했다. 전120세계를 보존한 채 **해당 교체 후보에서 현재 선택된 유한 작업 담당자를 제외하는 한 조건**만 추가한 `commitment_safe_swap`을 별도로 실행했다. 물리 조건·기한·보상·학습률·신경망은 바꾸지 않았다. 사후 개발 진단이며 새로운 미사용 평가 성능이 아니다.

4대/계열별6세계의 실제 값:

- D_visible: 기존 관측 예비 배치가 작업100%/위협 통과16.67%/동시 성공5/6. 보완 규칙은 작업100%/통과0%/동시 성공6/6.
- E_incumbent: 기존 READY는 작업66.67%/통과100%/동시 성공0/6. 보완은100%/0%/6/6.
- E_successor: 기존 READY와 관측 예비 배치는 작업66.67%/통과0%/동시 성공0/6. 보완은100%/0%/6/6.
- B_normal: 기존 READY도 이미100%/0%/6/6이다. 이곳에서 새 규칙은 필요하지 않았다.

비용도 함께 증가했다. D_visible 보완의 기존 공백은 평균8.625/64구역-초(CGR13.4766%)로, 기존 관측 예비 배치1.7917/64보다 컸다. B에서도 READY0에 비해7.375/64가 생겼다. 조용한 구역을 비우고 현재 확인된 공격을 막는 선택이므로 현재 위협 통과0만으로 책임 유지가 더 좋다고 주장하지 않는다.

작업이 가까운 worker 위치에 t=2에 생기는 A_near2대에서는 Fixed/READY6/6 동시 성공, 보완 예비 배치0/6이다. 작업이 생길 곳에서 미리 이동한 비용이다.4대 A_near도 보완 작업 성공률66.67%/동시 성공0/6이다. 전체120개 혼합의 보완 동시 성공76/120은 분포를 임의로 섞은 개발 요약일 뿐 일반 성능 순위가 아니다.

기존 Fixed/Greedy/Exact/기존 Handover/READY/적응/예비 배치/lookahead와 모델5개의 계열별 작업·마감·CGR·응답·완료·인계·전환 지표를 `analysis_final/all_method_summaries.json`과 최종 CSV에 함께 남겼다. 실패한 첫 규칙은46/120 동시 성공으로 그대로 보존했다. 강한 규칙의 실패를 골라 CAH 필요성을 주장하거나, 보완의 성공만 골라 보편 우위를 주장하지 않는다.

## 5. 미래 정보와 의사결정의 구분

기존108쌍에서 t<2의 누적 공개 관측·실제 요청·정책 메타데이터가 같았다. 그러나 엄밀히는 기존 Native의 `reset(config.seed)` 값은 분기마다 달랐다. 기존 결정 규칙은 저장한 RNG를 선택에 사용하지 않았지만, 임의의 새 정책이 seed 번호를 악용할 수 있는 API 여지는 있다.

이 차이를 숨기지 않고 모든 Native의 실제 reset 입력을7로 고정한216회를 추가 실행했다.108쌍의 이력이 여전히 같았고 기존 지표도 모두 같았다. 기존 코드는 수정하지 않았다. 후속 학습 환경에서는 사건 seed를 예측 특징으로 제공하지 않는 계약을 유지해야 한다.

Actor5개×두 모드×두 팀 크기×6쌍=120쌍도 공통 샘플 난수로 실행했다. 실제146차원 관측·slot ID·mask·관측 token·확률·sample·과거 행동이 t<2에 같았다. Critic·시나리오 seed·미래 작업은 Actor 입력이 아니다.

이 두 분기를 같은 확률로 낸다는 제한된 문제에서 동일 관측 이력만으로 미래 분기 라벨을 미리 맞히는 정확도 상한은50%다. reset seed를 단서로 허용하는 임의 API 정책까지 포함한 상한도, 실제 축구의 일반 예측 상한도 아니다.

같은 물리에 미래 작업 위치를 미리 알려준 특권 진단은2대 A_near6/6→6/6, D_visible0/6→4/6 동시 성공이었다. 남은2개는 위 물리 하한과 일치했다. 정보만 달라져 결과가 바뀌는 증거지만 실행 가능한 온라인 기준선이나 현실 센서 성능은 아니다.

실제 RoboCup에서는 공/상대 궤적이 미래 작업의 단서가 될 수 있다. 그러나 현재 로컬 자료에는 그 단서와 미래 작업 발생을 연결한 GT 평가 집합이 없다. 예측 성능은 미측정이다. 이 시뮬레이터의 외생 미래 분기를 “더 학습하면 반드시 알아낼 수 있는 패턴”으로 부르지 않는다.

## 6. 실물 파라미터와 현실성

실제 소스·보관 자료29항목과 서비스 timer 보충3항목을 조사했다. 주요 결과와 원문 근거는 `ROBOT_PARAMETER_EVIDENCE_KO.md`와 `evidence/*.json`에 있다.

역할 시험 명령 상한0.20m/s·회전0.50rad/s, 일반 설정0.40/1.0, 목표 허용0.15m/15도,20Hz 행동,50Hz tracker timer,2Hz 팀 송신은 **코드 설정**이다. 정지 pose30Hz와 작은 변동, shadow 추론0.29ms, 과거 피드백 간격은 **각 기록의 범위에서만 확인된 값**이다.

실제 최대/운용 속도, 회전 시간, 목표 도착 지연·절대 오차, 명령→운동 지연, 절대 자기위치 오차, 공 추적 종단 지연/유효 갱신 주기, 다중 로봇 단방향 통신 지연, 성공 복구시간, 상대 위협 도달 예측 정확도의10항목은 미측정이다. 추정 숫자로 채우지 않았다.

현재 sim의 이동1m/s/회전πrad/s,0.25m READY,2초 응답 예산,2/12초 작업 점유,1초 제어는 실물 보정값이 아니다. 회전 후 직선 이동과 실제 횡이동/동시 회전도 다르다. 경계 없는 점 환경이고120개 중108개의 초기 로봇/작업 축 정렬 span이 연습장3.9×2.6m를 초과한다. 실제 지도 등록 없이 연습장과 동일하다고 할 수 없다. 실전 지도9×6m와 연습 지도의 소스 규격도 따로 확인했다.

## 7. 파라미터와 시간 해상도 민감도

같은40세계에서 위치·작업시간·마감·사건을 유지하고 한 항목씩 바꿨다. 아래 보완 규칙의 작업 성공률은 에피소드별 작업 비율의 평균, 동시 성공은 모든 작업과 명시 위협을 함께 성공한 에피소드 비율이다.

- 원래 가정:작업83.50%, 동시 성공67.50%.
- 이동 속도 배율0.4:작업47.17%, 동시 성공25.00%.
- 이동 속도 배율0.2:작업36.67%, 동시 성공10.00%.
- 회전 제한1.0rad/s:작업83.50%, 동시 성공60.00%.
- 회전 제한0.5rad/s:작업83.50%, 동시 성공60.00%.
- 작업/위협 전달1초 지연:작업65.83%, 동시 성공40.00%.

속도0.2 배율에서 guard가0.2m/s가 되더라도 실제 로봇이 이를 정확히 추종한다고 검증한 것은 아니다. 느린 worker 비율도 가정 그대로다.1초 지연은 합성 정보 전달 조건이지 실제2Hz 네트워크 지연 측정이 아니다. 원래5방법의 동일 실험1,200회와 보완240회를 모두 저장했다. 방어만 보면 작업을 포기한 느린 정책이 좋아 보일 수 있어 작업 성공과 분리했다.

물리 dt0.125와0.0625의96쌍에서 작업 성공률·마감 초과·위협 통과·동시 성공 변화는 모두0쌍이었다. 기존/물리/작업 후 공백, 응답/완료/인계 시각의 최대 차이는0.0625초였고 소유권/위협 가중 공백 차이는0이었다. 제어 판단은 모두0~31초의1초 간격, 외생 사건도 같았다.

**현재 추상 환경 비교의 제안 기준은 물리 dt0.125초**다. 마감/위협 도달과 차이가0.125초 이내인 새 경계 사례는0.0625 이하 재검사를 요구한다. 이번96쌍이 연속시간의 모든 임계 조건을 보증하지는 않는다. 실제 행동 노드20Hz와의 연결에는 제어 주기도 별도 고정·검증해야 한다. 실물20Hz의 타당성을1초 제어 진단으로 대신 검증하지 않았다.

## 8. 지표의 해석과 복구

기존 CGR을 보존하되 정확한 분모를 구분했다. **legacy CGR은 위험도 가중 공백/위험도 가중 구역시간**이다. 새 소유권/물리 공백의 무가중 분모는2대32/4대64구역-초다. R_changed에서 기존 가중 분모는104/136까지 늘므로 raw 공백 초를 그 분모로 나눈 값이 원래 CGR이라고 할 수 없다. 최종 `coverage_denominator_details.json`에 가중/무가중 분자·분모를 함께 저장했다.

위협 가중 공백은 강도×진행 시간의 별도 위협-초를 분모로 쓴다. 현재 응답 가능성은 작업 종료·회전·제어 대기를 반영한 ETA 매칭이며 실제로 대응 명령을 선택했다는 보장이 아니다. 명시 담당자가 있어도 멀거나 작업 중이면 실제 방어를 실패할 수 있다. 실제 통과는 도달 순간의 용량·위치를 GT로 재검사한다. **통과율은 실제 실점률이 아니다.**

작업이 실패하면 작업 후 공백은 정의할 수 없어 null이고, 원래 위협이 없는 세계도 통과율 null이다. 과거 위협 미모델 로그의 “알 수 없음”은 새 세계의 명시적 “위협 없음”과 다르다. 완료한 작업만의 응답/완료시간과 성공률을 반드시 같이 본다.

신규 복구 진단은 고장 직전 실제로 맡던 base에 대해 “고장 이후 가동 중·다른 유한 작업에 묶이지 않은 로봇이 다시 그 지점에 있는 첫 시각”을 raw GT에서 계산한다.0초면 처음 서비스가 이어졌다는 뜻이고 장치가 즉시 수리됐다는 뜻이 아니다. 해당 base가 없으면 null, 관측 끝까지 돌아오지 않으면 우측 검열이다.

보완 규칙의4대 기존 담당자 고장에서 이 지점 서비스 복귀 지연 평균1.25초였다. 후임 고장에서는 당시 담당하던 조용한 base1의 복귀 평균10.7083초였다. 공격받는 base0를 방어해도 다른 구역의 복구는 늦을 수 있다. 이것은 시뮬레이션 서비스 지표이며 실물 낙상 복구시간이 아니다. 실제 성공 복구시간은 여전히 미측정이다.

## 9. 검증·보존·개발 중 발견 사항

최종 근거는 `completion_final/audit.json`, `unittest.txt`, `final_integrity.json`이다. 새 raw5,022개를 기존 평가 함수로 다시 계산해 저장 결과와 대조하고, Actor 표본46,080개의146/10 shape·mask·sample/log-probability·디코딩 요청 일치와 미래 작업 피드백 부재를 검사했다. 기존216개 회귀+신규27개, **총243개 테스트가18.429초에 통과**했다. 실패/오류/skip은0이다. 실제 전체 출력은 위 unittest 파일에 기록했다.

기존 소스219개와 선택 checkpoint5개는 SHA256 보존, 기존 출력29,786개는 크기/수정시각 보존을 확인했다. 출력 전체 내용을 재해시한 것으로 과장하지 않는다. 실물 소스와 근거 파일도 읽기 전용 해시를 보관했다.

개발 중 첫 인계 규칙의 worker 간섭을 발견해 원형과 보완을 별도 저장했다. 초기 요약에서는 빈 defaultdict 키도 성공 증인 목록에 들어가는 오류를 발견했다. 중간 `analysis/`는 보존하고 `analysis_final/`에서 실제 비어 있지 않은 증인만 집계했다. 정책 실행값과 원인 수량은 바뀌지 않았으나 세계별 증인 목록은 수정됐다. 이를 검출하는 단위 테스트를 추가했다. 기존 reset API의 seed 차이도 추가 재현으로 검증했다. 중간 감사241개와 최종 추가 검사 결과를 구분한다.

이번에는 모든 신규 파일을 `research/cah_mappo/`에만 생성했다. 기존 연구·ROS2·Isaac·보행/킥/복구 정책은 수정하지 않았다. 설치·원격·실물 실행·Git 커밋/푸시·외부 전송·새 학습은 없었다. 기존 사용자 변경은 보존했다.

## 10. 판단과 남은 한계

인계 비용은 존재하지만 이번에 해결한 주요4대 실패는 단순한 공개 정보 규칙의 담당자 보호와 구역 교환으로 해결됐다. 정보가 같은 미래 분기는 학습만으로 확실하게 구별할 수 없다. 일부 사례는 현재 행동/용량 하한 때문에 실패한다. 나머지7세계와 고정 모델의 전이 실패는 미확정 원인이 남아 있어 숨기지 않는다.

이 결과로 CAH-MAPPO 필요성이나 모든 규칙의 충분성을 주장하지 않는다. 실측 속도·지연·작업 점유·위협 모델이 아직 없고, 가정을 바꾸면 정량 결과도 달라졌다. 따라서 **현 단계에서 새 학습 구조 연구는 진행하지 않고, 후보 C의 실물 제약 기반 비교 연구로 범위를 정하는 것을 권고한다.** 후보 A/B/C의 기여 가능성·장비·강한 비교군·준비 범위와 구체적 후속 계측안은 결정 문서에 있다. 이후 개발과 계측은 자동으로 시작하지 않는다.
