# Phase 5B-1 P0 현장 비구동 검증 절차

작성일: 2026-11-23. 상태: 오프라인 준비 문서. 현장 실행·로봇 연결 승인이 아니다.

이번 작업에서는 센서·구독기조차 실물에서 실행하지 않았다. 현장 담당자가 별도 승인 후 수행할 절차다. P0 기록이 성공해도 토크·직선 이동·회전·킥·기상·경기 실행은 승인되지 않는다. 기존 PHASE5B1_PREFLIGHT_KO.md와 Phase5A 측정 프로토콜을 대체하지 않는다.

## 1. 장비 담당자와 안전 담당자 지정

조작자와 안전 담당자의 이름·연락 방법·권한·작업 일시를 남긴다. 한 사람이 PC 화면만 보고 로봇 보호까지 담당한다고 가정하지 않는다. 사용할 로봇 ID, 정확한 모터/배터리 모델, 전원 구성, 측정 PC와 저장 장치, 예정 센서만 목록으로 확정한다.

제조사 자료 또는 장비 담당자가 승인한 온도·전류·전압 중단 기준과 출처를 확보한다. 과거 기록의 온도·전압 범위나 소프트웨어 낙상 판정각을 안전 한계로 복사하지 않는다. 자료가 없으면 미확정으로 표시하고 장비 사용 판단을 보류한다.

## 2. 전원 및 구동 상태 확인

지지대·완충재·추락 방지를 확보하고 사람과 물건이 작업 범위에 들어오지 않도록 한다. 토크 OFF 상태의 로봇을 지지 없이 세우지 않는다. 담당자가 확인한 전원 계통도에 따라 모터 구동 전원과 컴퓨팅/센서 전원을 구분한다. USB 또는 MCU 재연결이 모터 계통에 미치는 영향을 확인한다.

확인된 물리적 격리와 장비 상태 확인 기록 없이 소프트웨어 Bool, 버튼 상태, cmd_vel=0, gait=stop을 비구동 증거로 쓰지 않는다. 상태를 모르면 실행하지 않는다. 비상 시 누가 어떤 장치로 전원을 차단하고 로봇을 지지할지 정한다. P0 중에는 START·토크 ON·목 스캔을 시험하지 않는다. 비상정지 검증에 구동이 필요하면 P0 범위를 넘는 별도 절차·승인을 받는다.

## 3. 기록 장치·저장 경로 확인

고유 experiment_id/robot_id/trial_id, 반복 번호, 바닥·전원·센서 조건을 기입한다. 기존 trial 디렉터리를 재사용하지 않는다. JSONL 상태 기록, 원본 bag, 독립 GT 영상, 교정 파일의 보존 경로를 구분한다. 원본은 편집하지 않고 분석은 복사본 또는 읽기 전용 입력으로 수행한다.

실제 기록 장치의 여유 공간과 지속 쓰기 성능을 확인한다. 이번 오프라인 PC의 디스크 값은 로봇 디스크 검사가 아니다. 기록시간은 첫 예비 구간을 30초로 계획하되 담당자가 승인한 상한과 저장 예산을 넘기지 않는다. 이는 통계적 충분성 또는 장비 안전 한계가 아니다.

848×480, 30fps, BGR8 색상과 16UC1 깊이를 각각 한 번 원본 기록한다는 가정에서 payload만 초당 61,056,000byte, 30초 1,831,680,000byte다. DDS/bag 부가 정보·별도 GT 영상·복제 저장·파일 시스템 여유는 별도다. 실제 encoding/stride/프로파일·압축 상태를 확인해 예산을 다시 계산한다. 원시 이미지를 JSONL 숫자 배열로 기록하지 않는다.

## 4. 타임스탬프·좌표계 계약 확인

각 장치의 clock ID와 시각 의미를 적는다. ROS time은 use_sim_time 여부, 시스템 시계 변경 여부를 확인한다. bag 기록 시각, 수집 콜백의 ROS now, 메시지 header, 외부 영상의 노출/PTS를 별도 열로 유지한다. 콜백 시각은 커널 도착 시각이나 센서 측정 시각이 아니다.

시계 연결마다 offset의 부호, 측정법, 잔여 오차, drift, 유효 시작/끝, 기준 장치·담당자를 기록한다. 시각 공통 단서가 없다면 cross-clock 지연은 결측이다. 한 clock 내 역전 없음이 다른 clock과의 동기화를 증명하지 않는다.

map/odom/base_link/imu_link/카메라 optical/GT 좌표계의 원점·축·단위를 기록한다. 카메라 프레임 이름을 확인하여 manifest.frames에 등록한다. TFMessage는 transforms 각각의 parent/child/header 시각을 점검한다. /tf_static의 0 stamp는 허용될 수 있다. /joint_states 또는 /joint_goals의 빈 frame은 관절 각도 정보라는 의미와 함께 남기며, 이를 map 위치로 해석하지 않는다.

## 5. 비구동 상태의 센서 기록 가능 여부 확인

현장 승인된 센서 구성만 시작한다. 이 문서는 실행 명령을 제공하거나 자동 실행하지 않는다. `real_base`, `dynamixel_system`, `real_role_trial`, `control`, 기존 base/start 운영 스크립트는 P0 센서 실행기로 쓰지 않는다. 모터·버튼·목 제어 경로가 함께 포함된다.

MCU 브리지는 IMU ON/PING/watchdog 명령을 쓰므로 순수 수신기가 아니다. firmware와 물리 격리가 확인된 뒤 별도 검토한다. IMU parser는 입력 바이트를 해석하는 분리 후보지만 실시간 원천 확보는 별개다. 카메라 역시 외부 드라이버의 USB 초기화·설정 변경을 포함하므로 확인 없이 안전을 확정하지 않는다.

기존 JSONL 수집기는 이미 승인된 토픽을 구독하는 도구다. 생산자 시작이나 전원 격리를 하지 않는다. 센서 프로파일별 필수 스트림을 선언하고, 구독이 만들어졌다는 사실과 실제 메시지 수신을 구분한다. silent event는 결측 스트림으로 오판하지 않는다. 메시지 type·offered/requested QoS·durability·수신 수·데이터 신선도를 기록한다.

기존 구조에서는 실제 관절 feedback/모터 진단에 body_motor_controller가 필요하다. 이 드라이버는 시작 시 모터 설정을 쓰므로 P0 목적으로 켜지 않는다. 별도 읽기 전용 bus reader는 검증되어 있지 않다. 이 경우 joint/진단/동적 neck TF/세계모델 일부가 없다는 사실을 남기고 합성값으로 대체하지 않는다. replay/GUI 관절 값은 실물 측정값이 아니다.

## 6. 독립 기준 장비 교정·동기 확인

PHASE5B1_P0_GT_REQUIREMENTS_KO.md에 따라 카메라 고정, 거리 기준, 추적점, 교정 잔차와 독립 검증점 오차, 영상 시각의 의미와 동기 오차를 확인한다. 이 단계의 GT 부재는 기록 도구 시험을 막는 이유와 구분할 수 있지만, 절대 위치·속도 정확도 평가와 P1 진입은 불가다.

## 7. 제한된 기록과 무결성 확인

승인된 짧은 구간만 기록한다. 시작/종료·오류·중단 이유를 수동 이벤트로 기록한다. 시간 상한, 공간 부족, write/fsync 오류, 예상 밖 제어 프로세스나 동작, 전원·열·전류 이상, 지지 불안정, GT/시각 상실이면 현장 절차에 따라 중단한다. 자동 재시작·반복하지 않는다.

센서별 수신 수, 간격 분포와 긴 간격, header/수신 시각 역전, 좌표계, decode 오류, 종료 후 JSONL 마지막 행의 온전함을 검사한다. 긴 간격은 누락 후보이지 패킷 손실 확정이 아니다. 필수 스트림이 0이면 실패다. /tf_static은 늦게 참여한 구독에서도 확인하되 실제 offered QoS와 맞아야 한다.

기존 subscriber의 실제 DDS 연결·성능·프로세스 강제종료·디스크 부족/부분 write 복구는 이번에 인증하지 않았다. 쓰기 오류나 비정상 종료가 있으면 세션을 불완전으로 보존하고 새 trial로 재개한다. 원본을 고쳐 정상 데이터처럼 만들지 않는다.

## 8. 원본 봉인·결과 재생성

모든 기록기를 정상 종료한 후 count/파일 크기/sha256을 확인하고 원본·설정·교정·clock 자료·오류 일지를 봉인한다. 같은 원시 입력에서 분석 결과를 다시 생성해 동일성을 확인한다. 이번 오프라인 예제처럼 결과 경로는 매번 새로 만든다. 동작 영상·bag·clock 자료의 대응 관계를 남긴다.

장비 담당자와 안전 담당자가 현장 P0 결과를 검토한다. `onsite_evidence_UNFILLED.json`은 빈 확인 양식이지 서명 증거가 아니다. 필드만 채워졌다고 장비 안전성이 자동 인증되지 않는다. P1 이동 실험은 아래 문서의 미충족 항목 해소, 실제 현장 기록 검토, 별도 사용자 승인 후에만 검토한다.

## P1 진입 판정

현재는 **진행 불가**다. 안전 담당자/기종별 중단 수치/비상정지·기구 보호/실제 설치 정책/독립 GT 교정/시각 잔여 오차/현장 P0 성능/실제 저장 공간/현장 실험 승인이 확인되지 않았다. P0 오프라인 준비 완료와 현장 P0 검증 완료를 혼동하지 않는다.
